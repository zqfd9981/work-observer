# Work Observer 招聘市场与职业演化研究

Work Observer 以招聘信息为主要证据，持续研究市场上的工作种类、职责结构和能力要求如何变化，并帮助个人理解这些变化对自己的意义。项目同时提供岗位筛选与求职准备支持。

重点梳理的关系是：**企业的业务背景与目标 → 需要完成的任务和交付物 → 承担任务的岗位 → 所需能力与使用工具，以及这些关系的持续演进。**

当前处于开发准备阶段：已创建目录并整理设计文档，尚未实现功能。前端形式后续再定，先通过命令行和后端接口验证核心过程。

## 项目目标与第一版范围

第一版先面向国内 AI 应用与 Agent 相关岗位，接入一个招聘来源，从一个城市与有限关键词开始。观察范围需要记录和版本化，样本结果不能直接代表全国市场。

计划完成以下过程：

1. 定时获取职位列表，采集新岗位详情，周期复查已有岗位；支持手动补充文本、链接、截图等材料。
2. 保存岗位身份、原文、观察记录和历史快照，识别重复发布与内容变化。
3. 分析工作任务、责任、交付物、能力与工具，建立可追溯的岗位画像和领域认知。
4. 研究 Agent 根据问题与中间证据选择检索、比较、统计和补查工具，输出有依据的研究结果。
5. 持续更新领域理解、研究假设、跟踪方法与记忆，用评测决定新策略是否试用、保留或回退。
6. 根据个人偏好筛选岗位，生成更新报告、待核实事项与关注提醒。

第一版暂不覆盖自动投递、联系招聘者、完整简历编辑或跨平台全量采集。先把真实数据与研究过程跑通。

## 已确定的架构方向

- **一个研究 Agent 配合固定业务流程。**程序承担采集、去重、存储和统计；Agent 根据证据决定调查路径，不只在流程末尾写报告。
- **SQL 与 RAG 配合。**确定的筛选和统计使用 SQL；解释性研究检索原文、历史和相关资料，组成证据包交给模型。首版先做范围过滤、标签、别名与关键词检索，向量检索按评测结果扩展。
- **业务数据与记忆有明确归属。**岗位、知识、偏好和人工纠正保存在业务库，摘要关联权威记录；研究线程检查点单独保存。
- **改进需要反馈和验证。**Agent 可以提出领域认识和跟踪策略，但候选不能自己修改验收标准。固定评测与发布流程负责比较、试用、监测和回退。
- **先保持单机、单长任务 worker。**长子任务或人工审核等待时保存检查点并释放 worker，避免父任务阻塞等待子任务。

计划采用 Python 与 uv、Pydantic、SQLite 与 SQLAlchemy、LangGraph、MCP 客户端、Typer 和 FastAPI。具体依赖版本在工程初始化与兼容性验证后锁定。首版不单独建设通用记忆平台、图数据库或多 Agent 系统。

## 后续开发顺序

| 里程碑 | 主要工作 | 完成依据 |
| --- | --- | --- |
| M0 独立连接 | 初始化工程，确认招聘 MCP 的启动或连接方式，验证模型与公开搜索接口 | 独立程序取得真实职位列表和少量详情，明确字段、认证、错误与运行条件 |
| M1 采集档案 | 建立岗位身份、原文归档、观察记录、快照与去重 | 相同数据运行两次，不重复造岗位，保留观察历史，失败状态正确 |
| M2 定时采集 | 接入定时触发、持久化任务、运行租约、断点与认证异常处理 | 无需每天发起聊天也能运行，失败可追溯，开始积累真实历史 |
| M3 岗位画像与证据 | 实现结构化解析、截图导入、分类与原文片段关联 | 能解释不同岗位的任务差异，关键判断能回到原文 |
| M4 RAG 与知识基础 | 实现范围过滤、检索、比较统计、偏好纠正和基线评测 | 检索与时间版本正确，统计口径明确，偏好可更新，基线可复现 |
| M5 研究与改进实验 | 接入 Agent 工具循环、长期记忆、补查与候选策略实验 | 能根据证据选择下一步，区分通过、失败和证据不足，不修改自身门槛 |
| M6 接口与发布验收 | 完成接口、报告收件箱、记忆管理、限量启用与回退 | 无前端也能完整使用，任务不死锁，策略版本和研究结果可追溯 |

先完成每一步的验收，再扩大范围。M1 可靠后尽早推进 M2，先积累真实历史，不等待研究 Agent 全部完成。自我改进等有基线和评测规则后再开始，不先搭独立的自进化平台。

## 下次从这里继续

启动开发时，先阅读项目方案的“开发顺序与每一步的验收”，并对照架构文档的模块合同，开展 M0：

1. 初始化 Python 与 uv 工程，只添加当前步骤需要的依赖。
2. 确认招聘 MCP 是本地进程还是远程服务，核实独立客户端的认证和运行方式。聊天中可用的工具不等于本项目已具备连接能力。
3. 用独立程序读取实际工具结构，搜索一页岗位并获取少量详情，保存真实响应样例，确认身份字段、分页和错误结构。
4. 确认并验证可独立调用的模型与公开搜索接口，记录可用条件。
5. 根据实际结果补充文档，完成 M0 验收，再进入 M1 的归档与入库。

推进时持续遵守以下约定：

- 完成里程碑后更新本 README，记录实际验证结果与未解决事项，不把设计或占位目录当成功能完成。
- 区分原始事实、模型推断、人工纠正、模拟样本和真实运行数据；所有关键研究结论保留证据。
- 固定观察组和探索组分别记录，采样或分类变化不能直接解释为行业趋势。
- 新策略先与基线比较；证据不足时保留基线，回退保留原始资料和变更历史。
- 前端、额外 Agent、向量或图谱存储根据后续验证需要再加入。
