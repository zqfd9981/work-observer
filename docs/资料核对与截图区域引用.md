# 资料核对与截图区域引用

2026-11-19。此阶段补充的是可操作的数据核对闭环，不恢复暂停招聘来源，不自动合并岗位，也不宣称OCR能可靠定位图中文字。

## 跨入口疑似重复

页面“资料核对”点击“检查本地资料”，比较最多300个本地岗位。结果同时列出完整范围、实际扫描数量、疑似对数与截断说明，最多展示50组。范围超过上限或候选超过展示数量时明确提示，不能把本次命中数解释为全库完整重复率。

仅相同标题或公司名称不会形成候选。规范化正文相同、正文与标题同时相近，或已保存链接结合其他相似依据才形成疑似；页面并列公司、标题、来源、正文预览和城市/薪资/学历/经验等不同字段。规范化和字面相似会产生误报、漏报，不能确认招聘主体或职位身份。

人工填写核对说明后，可以关联为疑似同一岗位、确认不同或撤回关联。每次变更新增审核版本；相同请求幂等。审核时冻结两份资料指纹，岗位资料后来改变会显示关联需复核。关联不会改写、删除或合并任何岗位、正文、观察和来源，现有统计仍按原始岗位记录计数。

## 截图区域引用

1. 从“补充资料”上传PNG/JPEG/WebP，人工核对转录文字并保存岗位；不必调用视觉模型。
2. 到“资料核对”刷新，选择图片关联的具体正文版本。只列出确有图片来源关联的已核对正文，不能任意给其他岗位贴上图片依据。
3. 在原图上按住拖动框选，也可输入0至1的左/上/右/下相对坐标。坐标以原图左上为原点，不修改或重编码原图。
4. 在已存正文中选中文字，点击“采用正文中选中的文字”；也可输入精确字符起止与引用。正文偏移按Unicode字符计数，包含emoji时仍与服务端一致；每条最多700字符。
5. 逐字核对图片区域和正文引用，勾选人工确认后保存。服务核对正文快照、观察/文档关联、引用区间、原始文档SHA和图片SHA。

保存后可在原图缩略图上回看区域、逐字引用、字符区间及SHA。每次读取重新核验原图和来源完整性；来源缺失或变化单列异常，当前岗位后来改版则单列历史正文。区域坐标始终标为人工选择和核对，`is_ocr_detected_region=false`，没有把模型输出伪装为自动定位结果。

可以撤回区域引用，原图、正文与引用记录保留。重复保存同一图片/文档/快照/区域/文字区间返回原记录；已撤回记录不会因为重复提交而自动启用。页面展示最近最多300条区域记录。研究或检索是否采用某条区域仍需核对具体引用范围，不能因存在一张图片就把整段正文都当作已完成区域核对。

## 服务合同与验收

`data_quality_routes(repository,response,read_json,busy)` 提供：

| 路径（均在 `/api/data-quality` 下） | 操作 |
| --- | --- |
| `POST /duplicates/scan` | 有界本地疑似发现，可指定 `job_ids/limit` |
| `GET /duplicates/reviews` | 当前审核与资料变更后的过时提示 |
| `POST /duplicates/review` | `left_job_id/right_job_id/decision/reason`，追加人工审核 |
| `GET /screenshot-targets` | 可核对的图片—正文版本关联 |
| `GET /regions` | 已存区域与当前完整性，可按 `job_id` 查看 |
| `POST /regions` | 图片/岗位/快照/文档、`bbox/start/end/quote/reviewed/note` |
| `POST /regions/{id}/withdraw` | 撤回引用，保留原始资料 |
