# 0.13 复核反馈补查与阶段验收

2026-11-19，单用户本地Alpha，持续目标保持active。交付“拒绝意见→明确新一轮→重读原文→再次核对”的直接研究闭环；没有自动学习用户偏好、自动采纳知识或默认启用新方法。

## 实际使用

打开“研究质量核对”，逐条核对已生成回答并保存拒绝意见。当前结果、原文、记忆和方法仍有效时，页面显示“参考本次复核重新研究”，可选择本轮最多调用、秒数或只预览。点击“新建这一轮（预算另计）”才开始，读取质量记录本身不会启动研究。新结果页和Markdown保留复核来源、评审类型与诊断说明，旧答案及消耗额度原样保留。

当前只支持已完成的直接研究、原问题、原岗位集合和原筛选条件；禁止公开搜索，使用标准研究工具加显式反馈策略。项目结果须继续使用项目总预算，不能走该入口另开额度；画像、日常流程和队列未接入这条新路径。CLI可使用：

```powershell
uv run --locked work-observer research --question "与原运行完全相同的问题" --job-id <原岗位ID> --review-run-id <被拒绝运行ID> --max-calls 8 --timeout 240 --save
```

多岗须重复传入原岗位ID，筛选也需相同；加`--offline`只整理反馈与原文，不调用模型。接口沿用`POST /api/research`，新增可选`review_run_id`和`review_id`，服务端选定并保存当前复核ID，页面提交显式绑定该ID。复核已变化、原文/记忆/知识过时或范围不同会拒绝，不能用旧页面静默换意见。

## 诊断与来源的边界

新上下文只带复核总结、失败/待核维度与逐判断诊断，不复制旧结论正文或引用。诊断可以出错，必须重新查询和读取本轮原文；`reviewer_kind`保持原值，Agent意见不变成人审、用户偏好或事实证据。固定结果摘要、复核ID与摘要；诊断总长限制6000字符，总结1000、各理由300，超限按完整条目省略并计数。

每次调用前和收到回复后都检查复核版本；中断续接使用原复核、岗位和剩余预算，不能解绑、换意见或通过重启重置额度。引擎方法单独登记为`research-method-v6-review-feedback`，输入/上下文摘要包含反馈。普通默认方法仍为v5，摘要保持`39a1ac28…dff24`；来源分项的共享引擎摘要随改动更新，保守登记v9，没有为v9新增真实调用，也未变更项目/画像默认方法。

`feedback_from`只用于隐私清理回链，不写入事实继承`continued_from`。遗忘原运行所用的个人记忆时，关联的反馈新运行、未执行排队记录、检查点、报告及带出文本的无检查点报告一并清除；备份恢复后同样成立。独立备份和已下载副本仍是独立私有副本，不会跨目录自动删除。
