# 记忆修订与派生资格审计

2026-11-19，0.6增量。此处验收的是更新后的业务一致性，不把测试数量或来源ID存在称为语义正确率。

## 已复现并修复的实际缺陷

使用`data/project-verification`中原先真实5调用研究的隔离副本，保存其带JD引用的知识候选并采纳，再修订源研究所采用的一条纠正：源报告审计已为过时，但原实现仍将派生知识作为有效背景召回，`validity.eligible`仍为true。正式库、原研究存档与原文均未修改，没有新增模型或网络调用。

修复后，同一副本的知识不再召回，资格说明回链已变更的源记忆；原知识`status=active`、原结论及证据仍保留。`active`表达历史采纳动作，当前资格另行计算。私有复现记录：`data/phase06-memory-repro/before.public.json`与`after.public.json`。原研究的语义质量仍为既有待审状态，复现不把它重新认定为正确答案。

## 资格如何传递

- 每条记忆检查当前状态、版本、有效期、精确引用、记录时的SHA和当前来源版本。源记录改指另一份原文时，不能通过重新计算新SHA而静默替换原引用。
- 有`source_run_id`的所有类型继续检查权威运行；必须存在、完成，且它采用的记忆、关系、检索口径与更早`continued_from`仍有效。改写派生知识的文字不能移除原依赖。
- 已采纳关系使用同一源运行资格，并继续遵守领域定义版本、反例、冲突和单岗人工领域纠正。旧关系的状态不覆盖新的人类纠正。
- 继承的项目偏好与单岗纠正继续限制派生内容的适用范围。没有这些限制时，双岗研究中只引用A岗原文、明确限定A岗的知识仍可用于A岗，不要求当前范围包含整个旧候选集合。
- 没有自己引用的假设与方法仍依赖源研究，不能在源正文或偏好变化后绕过失效检查。其可用不表示假设已证实或方法效果已通过评测。
- 当前指纹对应的最新人类明确拒绝会阻断复用。Agent辅助pending不会将其恢复；后续人类明确重新审核通过同一当前结果才可解除此项限制。测试中的“人类动作”是合成机制标签，未冒充实际人类验收。
- 未完成、缺失权威档案、循环与审计预算不足，均给出具体原因并停止默认复用。历史结果照留，资料可据当前版本重新研究。

旧报告和统计摘要不是原始证据。准确续接仍需重读当前范围的原文；本机制不能仅凭引用存在保证“集合统计已正确解释为单岗事实”，这仍属于语义评估与人工核对的范围。

## 共用接口和存储位置

`MemoryService.audit(id,version=None,job_ids=None,project_id=None,at=None)`与`derived_eligibility(source_run_id,job_ids=None,project_id=None,at=None,evidence_ids=None)`返回`eligible/issues/checked_at/visited_nodes/limits`。问题项只含类别、依赖ID和原因，不复制私人内容。`validity`保留原字段并增加`dependency_issues`；报告审计增加`stale_dependencies/dependency_issues`。

`DependencyAudit`一次最多96节点、12层，范围缓存同样计入预算。它只读权威档案与已索引原文，不调用模型、网络或其他聊天历史，不通过`recall→audit_result→recall`互调。资格不足不会自动扩充模型预算。

`Repository.bind_research_store(store)`将当前业务库绑定到明确的检查点路径和命名空间，拒绝其他业务库的namespace。审计使用保存的路径和namespace只读打开文件，默认研究关闭临时连接后仍可核验；自定义检查点不能悄悄改读默认文件。没有绑定时仅尝试当前数据库同目录默认档案，找不到即报告缺失，不编造来源。

## 实际验收

12项新增隔离服务回归覆盖：

1. 偏好修订使多层知识、假设和方法停止召回，旧记录不删，改写后再采纳也拒绝。
2. 撤回、冲突及有效期沿依赖传递。
3. 双岗源研究的明确单岗引用可准确复用。
4. 全局摘要不能洗掉项目偏好或另岗纠正的范围。
5. 缺失/未完成源运行及不属于该源运行的引用不能采纳。
6. 自定义档案连接关闭后仍能核验，其他namespace拒绝。
7. `continued_from`循环与预算不足失败关闭。
8. 无自己引用的方法仍受源JD改版影响。
9. 显式选择原冲突值可恢复仍有依据的资格。
10. 改写源元数据不能重绑定冻结引用。
11. 人类拒绝、Agent pending与人类重新审核的资格区别。
12. 双岗源研究的无关B岗原文改版时，A岗明确原文引用仍有效；整份旧报告和没有独立引用的方法仍须重新核对。

此前记忆/统一知识/报告审计/整项目遗忘组合66项通过；新增引用指纹、冲突恢复及审核动作也分别复验。修复旧fixture时将虚构源ID替换为实际完成的隔离权威运行，没有为保持绿勾放宽缺源资格。正式版本总检查以阶段总台账为准。

遗忘闭包同时接入串行业务流程与有限检索试用：先收集全部相关运行/项目ID并记日志，再擦除工作流、更新面板、通知和试用评语/事件。工作流仅保留用于重试的依赖ID，不能在中断后遗留可复生的目标、摘要或反馈。原始岗位、截图和独立备份仍按已有边界保留。
