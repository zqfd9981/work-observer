# 0.7 真实研究闭环与阶段验收

2026-11-19，单用户本地 Alpha。整体目标继续进行；工程验证、开发复验、Agent辅助语义审核和独立人类验收分开记录。本轮未解除招聘暂停、未推送或对外发布。

## 真实工作流及失败

从正式库只读 SQLite backup 到私有隔离目录，选两份既有真实岗位正文，预先保存问题、来源版本、代码/方法摘要、调用和时间上限。语料此前已用于开发，全部是开发复验，不是新公司泛化或新的预留盲验。

真实模型串行完成两份画像、双岗比较和反例调查：23次调用；两份画像各含4次基础研究与1次补充，比较5次，反例8次。流程停在等待审核，未由开发 Agent 批准。画像/原研究、原文与原正式库均保留。

反例调查曾三次提交带“无加分措辞”解释的required判断，被旧词面护栏当作加分条件拒绝。最后终稿删除了这一聚合判断并改写其他条目；不能仅据该删除断言最终全部资格信息都遗漏。实际问题是三次误拒绝与对回答的干扰，语义遗漏另由逐条阅读终稿判断。

修正局部否定及两种方向的明确必备/加分混写，反馈改为修正具体问题并保留其他支持判断；同题按原项目refresh创建新轮，5次真实调用完成。原8次结果摘要未改，原项目预留仍累计至24次/360秒，不重置预算。该轮同时采用纠错说明和范围强度提示，不能把调用减少归因于单一改动。

独立匿名Agent复核两份反例回答后均拒绝：人掌顶层目标等控制边界未完整保留，一版还弱化明确资格强度。再补充职责/决策/执行/人工接管和强度核对要求，以原问题和来源做第三次明确开发复验，5次调用完成。人机边界和强度得到保留，但仍将“个人分工未知”扩大为“没有开发职责”，与原文明示搭建系统/自研框架不符；独立Agent仍拒绝。

本组实际模型调用总计33次，预先封顶36次；没有公开搜索或招聘请求，未继续反复调参追求同题通过。第三轮另有更明确完成条件、不同项目上下文，变化已披露。以上不能证明端到端研究已合格；没有真实人类批准或真实候选启用。私有预注册、原始记录、盲包、评语和逐次用量保存在data/phase07-real-workflow/20261119-1a0eeac1。

## 完整画像审核

原质量入口按基础research run/hash核对，覆盖不到随后生成的领域候选和向招聘方核实的问题。本轮新增完整JobAnalysis.id+原始row.result hash审核，逐项包含判断、领域、问题及六维理由；基础研究审核不能替代整份画像审核。

人类明确拒绝只使对应画像和缓存失效，重算生成新ID并保留旧记录，不把基础研究中仍有支持的事实一并否定。Agent待审/拒绝仅作反馈，不能冒充人类批准；partial、失效依赖、未知审核评分仍不能批准。原文没有披露某类信息不自动算坏岗位或画像失败，须在覆盖与未知处理理由中区分未披露和模型漏读。

首次真实盲审的旧绑定hash只覆盖基础研究。旧盲包、绑定和独立评语原件未改；逐项确认封存的全部可见判断、领域、问题、全文等语义字段与当前画像一致后，本轮才首次绑定完整画像hash并保存Agent意见。receipt明确披露该时序，不能声称旧hash早已覆盖补充。两画像仍为Agent辅助reject/pending，无人类批准。

网页“研究质量核对”及岗位画像可进入“完整画像核对”；CLI `work-observer product profile-quality list/packet/reviews/review`使用同一服务。动态匿名包可隐藏旧评分与身份字段，显式导出副本须另外保管。

## 固定问题、匿名核对与配对

新业务评测协议先锁定问题、完整来源范围、逐条完成条件、开发/预留分区、方法摘要及预算，再预约每题/方法唯一结果槽位。登记绑定权威run、方法/策略、实际有效提示上下文、来源精确片段及实际用量；失败和未完也占位保存。个人上下文单独变化、换方法标签或改版本文字不构成已证明的方法改进。

封卷后按随机不透明编号核对，页面不提前展示方法、run、实际用量或旧评分。逐claim、逐完成条件和六维均须给理由。封评前同一规范化声明审核名可追加修正，历史保留，最新评分计一次；不同审核者的分歧仍保留。封评后不能换结果或改本批评分。元数据隐藏和姓名声明不能证明真正盲法、身份或独立性。

只有足够的预留任务、有效来源与合同、独立人类任务/审核声明及业务门槛具备，才可能标为仅在冻结范围达到门槛；不自动启用方法。开发回顾、复用题、缺人审或未控制的上下文差异保持不足。业务评测只登记research完整输出；完整画像另由专属审核绑定，不把基础run冒充整份画像。

本轮两份既有真实输出已登记开发回顾：方法实际不同、策略一致、有效上下文摘要不同；原来只看memory/continued_from等引用ID的摘要相同，故修正为从权威checkpoint第一条用户输入对完整project_context和memory_context取摘要，只存摘要，不复制私人文本。缺历史时标无法完整核对上下文。实际配对为insufficient、人审不完整、上下文干预披露、未启用。已知方法身份的Agent复核与独立匿名Agent复核有不同意见，均是辅助意见，不拼成金标准或普遍正确率。

网页“研究方法核对”仅展示安全概览、开发问题、匿名包和封评后比较，不提前返回预留题或方法映射；配置仍由明确本机协议命令登记，不接受网页任意文件路径。详见[业务研究评测协议](业务研究评测协议与验收.md)与[完整画像审核](完整画像审核使用与验收.md)。

## 遗忘、备份与数据保护

新增5张检查点表按业务库namespace隔离，不迁移正式业务表。协议/提交/匿名映射/评语命中源run、项目或记忆依赖后整组擦除自由文本，保留ID及防复用摘要；完整画像审核在画像已删后仍可按ID索引重试清理。原始JD保留。显式导出及外部手工副本不宣称自动遗忘。

完整备份只复制目标namespace登记的research-benchmarks/<id>/corpus内两份source-only工件，校验内外摘要、8来源表、无访问上下文和不安全结构；冻结字节不重写，恢复只重定位live资料路径，不重新开放评测次数。其他namespace的5张新表记录不进入包，副本压实避免空闲页遗留。草稿检索评测的既有备份仍保留。

正式资料、原文、.env和来源风险暂停均须核对不变，真实研究和演示写隔离库。合成资料、人类actor机制测试和Agent辅助实际意见均明确标注。
