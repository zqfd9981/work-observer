# 分层记忆使用与验收

2026-11-19。新增的是本产品业务记忆，不读取 Codex 或其他聊天软件的历史。研究项目的当前任务状态仍归项目存档；记忆记录回链原始岗位或公开正文，不将旧报告当成新的独立证据。

## 操作

页面“知识与偏好”可保存明确偏好、人工纠正、待验证解释和研究方法经验，选择全局相关研究、指定项目或指定岗位，填写可选主体和有效期。时间输入明确按北京时间解释。研究知识从已完成研究的带引用结论保存为候选。

API 与 CLI 共用 `MemoryService`：

```powershell
uv run --locked work-observer memory-add preference "合成示例：优先关注上海" --subject 工作地点
uv run --locked work-observer memory-add hypothesis "合成示例：RAG工作可能更重评估" --origin agent --scope project --project-id <32位项目编号>
uv run --locked work-observer memory-add method "合成示例：比较之前先补查反例" --valid-until 2027-01-01T00:00:00+08:00
uv run --locked work-observer memory-change <记忆编号> activate
uv run --locked work-observer memory-change <冲突记忆编号> accept
uv run --locked work-observer memory-change <冲突记忆编号> reject
uv run --locked work-observer memory-change <记忆编号> revise --content "修订后的明确内容"
uv run --locked work-observer memory-change <记忆编号> withdraw
```

`POST /api/memories` 接受 `kind/content/scope/project_id/job_id/subject/valid_from/valid_until/origin`。知识候选另外需要 `source_run_id/claim_index`，由服务提取实际结论及引用，不能用请求体任填独立“证据”。`origin=agent` 的偏好与纠正始终先留为候选；知识、假设与方法无论来源都须显式采纳。API 不接受自设 `status=active`。

`POST /api/memories/{id}/{action}` 支持 `revise/withdraw/activate/accept/reject`；只有 `revise` 需要 `content` 请求体。`GET /api/memories` 返回资格检查 `validity`；`history=1` 查看历史，`project_id` 可限制项目记录列表。列表筛选不是模型范围授权，真正召回仍会检查项目与岗位。

## 一致性规则

- 偏好与纠正表达用户意图；知识是派生认识；假设是待验证解释；方法是研究经验。后三类均不构成新增原文。用户采纳方法也不表示方法的效果已通过真实质量评测。
- 项目记忆仅在指定项目中召回，岗位记录仅在候选范围含该岗位时召回；多岗位知识要求所有被引用岗位均在范围内。全局记录也按有界词面相关性召回，明确偏好优先，最多 8 条。
- 相同类型、范围、主体且有效期重叠的不同内容进入显式冲突，双方暂停召回。`accept` 选择一项并撤回与其有效期重叠的冲突项；`reject` 仅否决当前项，不自动猜测应恢复哪一项。有效期不相交的记录可并存。
- 内容修订新增版本，旧版停止默认使用；撤回或遗忘后旧值不会自动复活。范围、主体和有效期在一条版本链中保持不变，修改这些口径请撤回后新建，保留清楚的历史含义。
- 岗位知识重新校验快照、观察关联、精确字符区间和原始文件 SHA；当前正文不符时不默认召回。公开知识校验已归档原始字节与提取正文 SHA，后续同 URL 最新正文不同则标为来源变化。
- 公开公司资料可以支持背景认识，不能作为单岗位范围知识的依据。引用真实存在只证明可追溯，不能自动证明语义支持或公司主体相同。
- `active` 是用户采纳状态，不等于当前可用。页面单列有效期之外、来源已变及原文缺失；历史结果审计也检查这些情况，保留当时结论并提示重新研究。
- 个人偏好与纠正的忘记操作清除整条版本链内容、主体及引用，继续使用共用遗忘闭包清理受影响研究和派生认识。源运行失效也覆盖其假设和方法，阻断它们经后续摘要再次进入研究。原始岗位资料不删除；独立备份不自动改写。

## 验收与局限

已实现服务、迁移、API、CLI 与页面操作；本阶段机制验收使用隔离合成资料，不声称已经证明真实研究语义质量。

- 新增 10 项分层记忆单元验收：项目重开隔离、冲突与三项选择、跨有效期链不误撤回、有效期边界、模型推测待审、公开证据篡改/变更、忘记主体/派生方法，以及旧 e8 库增量迁移前备份与旧列值保持。
- 新增 4 项 HTTP/CLI 业务验收：项目字段与 Schema、显式冲突选择、候选状态保护、已过期 active 的说明和历史审计、CLI 范围与方法采纳。
- 记忆、遗忘及既有工作台/CLI 相关组合回归 49 项通过；Ruff 与网页脚本语法检查通过。新增公开正文样例是合成文件，未请求招聘来源，也未修改正式业务库。

主体冲突依赖用户或业务流程填写一致主体；没有把任意自由文本的逻辑矛盾识别称为已实现。召回仍是有界词面匹配，缺少跨主题语义质量证据。长期连续使用、真实研究效果和目标部署环境应分别验收，不能由本页机制测试代替。

## 忘记整个研究项目与失败恢复

`DELETE /api/projects/{id}` 通过当前报告目录执行整项目遗忘；运行中返回409，先暂停再操作。清除项目标题、目标、交流、调查步骤、范围历史及创建幂等参数，旧项目保留不能继续执行的最少状态。项目下全部偏好、纠正、知识、假设和方法及其版本都清除内容、主体和引用。

清除沿原运行、`continued_from` 跨项目派生和同项目其他轮次继续追踪，覆盖派生知识/关系、画像、业务审核、观察面板快照与更新报告、后续问题/通知和当前目录的JSON/Markdown导出。关系知识作为线索被后续研究读取时也保留源运行依赖，不能借没有直接 `memory_used` 绕过闭包。独立项目、原始岗位、观察、原图及独立备份保留；没有来源依赖的独立人工输入不凭文字相似推断归属。

`checkpoints.db` 的 `privacy_erasures` 按业务库命名空间保存依赖ID、完成标记和报告目录指纹，先记录已发现的回链再擦除正文。未完成操作在服务启动或CLI会话打开时继续本地清理，不触发模型或网络；完成日志不会在每次读取时反复擦除。即使进程在唯一上下文回链删除后退出，已记录ID仍能重放下游清理。

报告目录指纹采用 `sha256(str(Path(reports_dir).resolve()).encode('utf-8'))`，不保存原路径。恢复必须使用原报告目录；不匹配报 `PRIVACY_REPORT_DIRECTORY_MISMATCH` 并保持未完成，避免把错误目录的“文件不存在”当作清除成功。备份恢复到新位置时由恢复流程重定位该指纹。API在清理未完成或读取期间发生隐私变更时拒绝返回旧派生内容；成功的遗忘请求仍正常返回清理结果。

7项新增整项目遗忘机制验收通过：全类型项目记忆与跨项目/同项目下游、个人记忆经关系知识回链、清除运行回链后故障并重开继续、HTTP自定义目录及来源保留、运行中拒绝后暂停删除、命名空间隔离和未成功请求不留待执行任务、报告目录错误时失败关闭后正确续清。涉及既有个人遗忘与整项目DELETE的4项HTTP回归，在隐私读取保护接入后复验全部通过。机制样例仍为隔离合成资料，实际业务与部署验收由总台账单列。


## 研究自主提出假设/方法候选

受限工具propose_research_memory只能提交hypothesis/method，须引用本轮已读原文并指定已执行的本地工具行动。三个知识/假设/经验候选共享上限，标origin=agent及source_run_id，项目研究限定项目作用域，不自动改偏好或启用方法。一次工具命中不证明普遍改善。

新增3项隔离验证覆盖两种类型待审、明确采纳后召回、撤回后同次执行不重造候选，以及未执行工具行动拒绝；没有为该工具追加真实模型调用或宣称开放语义质量通过。
