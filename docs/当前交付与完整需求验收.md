# 当前可检查交付与完整需求验收

2026-11-19，0.16.0，单用户本地 Alpha。完整目标尚未完成，版本号不是完成比例。

## 直接打开工作台

本次交付的本机入口：[打开工作台](http://127.0.0.1:8776/#jobs)。仅当前机器可访问，需要本机服务进程保持运行。

工作台使用从封存真实研究备份恢复的独立副本：15个岗位、7份完整正文、8份摘要，21份研究运行记录、8份研究方法协议、24份方法审核和3份普通质量拒绝记录。运行记录包括未完成和失败；审核来自开发过程中的Agent辅助核对，不冒充独立人审。运行数、审核数和测试数不表示业务质量。

页面修改保存在副本中，数据库、原文、检查点和报告均与正式工作区分开。原始真实研究和正式资料保留。BOSS来源仍因code37暂停，未发起恢复、招聘采集或自动研究。模型配置沿用本机配置，只有明确发起模型研究才消耗调用；可勾选“仅整理证据，不调用模型”。

建议按以下顺序检查：

1. **岗位资料**：查看15个岗位，筛选“有完整正文”，打开正文、来源和历史。摘要不能充当完整正文。
2. **研究工作台**：查看研究历史及引用，区分完成、未完成与被质量核对拒绝；试用新研究时可先用离线证据包。
3. **研究质量核对**：检查既有拒绝意见和证据缺口。生成了回答并不表示审核通过。
4. **持续研究项目／知识与偏好**：检查多轮研究和分层记忆入口；副本继承已有内容，不为演示伪造已采纳知识或用户偏好。
5. **领域与证据／已存研究**：查看统一检索、定义及报告入口。缺少真实样例的方向仍需实际使用验收。

实际浏览器逐项交互尚未完成；此前浏览器读取因工具无法确认网址而停止，没有绕过限制。本机入口通过HTTP检查不替代完整页面验收。

## 当前真实质量结论

最近一次真实研究复验仍为0.15：基线5次调用生成回答，但资格条件覆盖有遗漏，部分术语解释不能由原文确定；候选8次调用仍未完成，没有证明方法收益。原记录、拒绝与失败保持，实验提示已撤回。详见[真实复验](资格否定误拦与0.15真实复验.md)。

0.16修复新标准研究的局部否定误拦，并版本化检查和旧轮恢复；完整640项测试及独立安装验证通过。本轮新增真实模型调用为0，因此不能据这些检查宣称上述真实语义问题已经解决。详见[本轮机制验收](版本化标准检查与0.16阶段验收.md)。

接下来的交付重点是实际页面操作、未见过的真实业务题及独立核对、多轮跨日使用和目标环境部署。功能入口已具备，可靠性和长期使用证据尚需补齐；完整目标保持未完成。

## 停止与再次打开

工作台启动文件位于本机私有目录`data/workbench-preview/launch.py`，使用已安装的0.16包。当前后台进程与HTTP检查收据在`data/phase16-release/workbench.public.json`，不包含密钥。

关闭当前进程后，可在仓库目录重新启动同一副本：

```powershell
& .\data\phase16-package\venv\Scripts\python.exe -X utf8 .\data\workbench-preview\launch.py
```

该启动入口固定使用副本的数据库、原文、检查点和报告。打开`http://127.0.0.1:8776`；结束前台启动可按`Ctrl+C`。原先README中的正式工作区启动方式继续适用于正式资料。
