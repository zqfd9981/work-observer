# 显式执行持久调查队列

2026-11-19。本入口补齐独立于网页进程的研究队列执行。它处理已持久保存的项目调查步骤，仍是一个研究 Agent 串行工作；不建立常驻服务、系统计划或应用自动化，也不保证 24 小时持续运行。

## 操作

先在工作台“持续研究项目”或 `product projects` 中明确目标、岗位范围和步骤。然后显式执行一次有限批次：

```powershell
uv run --locked work-observer research-worker --once --db data/app.db
```

只处理一个指定项目：

```powershell
uv run --locked work-observer research-worker --once --project-id <项目编号> --db data/app.db --max-steps 3 --max-calls 24 --max-seconds 600 --max-public 0
```

默认最多处理 3 步，整批硬上限为 6 步、36 次模型调用、900 秒预算、4 次公开搜索/正文调用。可以用 `--max-steps`、`--max-calls`、`--max-seconds`、`--max-public` 收紧；超出上限会被拒绝。未给 `--once` 不会启动。没有循环模式，退出后不会在后台继续调用。

若队列步骤全部明确为离线原文整理，可将模型和公开调用上限设为零：

```powershell
uv run --locked work-observer research-worker --once --db data/demo/app.db --reports-dir data/demo/reports --max-calls 0 --max-public 0
```

这不会把在线步骤变成离线步骤；在线步骤因额度不足保留队列，需在项目中明确选择原文整理或另行执行。模型研究完成后仍进入待审核；证据整理、资料不足进入等待资料。前置调查尚未审核完成的汇总步骤不会被自动执行，也不会占住 worker 等待自己未完成的子任务。补充资料、审核或新增追问后，再显式运行下一批。

恢复目录或使用自定义报告目录时，同时传入正确的 `--db`、`--reports-dir`；`--env-file` 可指定已有本地配置文件。入口会先继续未完成的本地遗忘闭包，目录不匹配时停止，不以缺失报告冒充已完成删除。不会打印配置密钥。

## 预算、恢复与范围

每步领取前，按其完整最坏预算预留模型调用和时限；允许公开补查的在线步骤一次预留 4 次公开调用。预留超过本批剩余额度就跳过该就绪步骤；项目内没有符合剩余预算的就绪步骤时，继续检查本次有限扫描中的其他项目。领取事务会重新核对实际选中的步骤，而不是相信扫描时看到的旧预算，因此队列在其他窗口被修改，也不能换入超预算步骤。

预留和实际记录分别输出。例如某步最多允许 6 次调用，实际只用了 3 次，本批仍按 6 次预留，不能把剩下 3 次悄悄分配给另一完整轮次。项目自己的累计调用/时间预留、轮次和公开来源限制也继续生效；进程重启或再次运行 worker 不重置项目预算。已中断的轮次沿用原运行编号、检查点、范围和累计额度。

整批持有业务库的跨进程研究锁，取得锁后才恢复和领取步骤。锁忙时不改另一个进程的执行状态；重启只在锁内将本次扫描中遗留的运行标为中断，再显式恢复。默认只扫描当前业务命名空间中最近更新的最多 100 个非遗忘项目，输出完整候选项目数和扫描截断标志；指定项目则仅处理该项目。工作台或其他入口新生成的步骤，可在本批剩余步数和预算内继续领取。

结果包含：处理的项目/步骤/运行编号、各步状态与停止原因、全局预留和实际计数、墙钟时间、等待审核/资料/前置步骤数量、预算跳过原因和扫描范围。等待项直接释放，不轮询、不自动花费下一批预算。原始岗位、公开资料及来源暂停保持原有约束；BOSS 的 code 37 暂停不会被研究 worker 解除。

## 验证级别

已用隔离合成资料和明确模型替身验证：整批按最坏预算预留、少量实际调用不会扩大本批和项目额度、显式重启不重置项目预算、恢复原运行编号、等待审核/资料及依赖不轮询、命名空间隔离、扫描与领取间队列换步的原子预算拒绝，以及实际 CLI 的 `--once` 和离线队列执行。测试不新增外网或真实模型调用。

长期无人值守、跨日稳定性、开放研究语义质量和目标部署环境尚未由此证明。该入口是可控的持久队列批处理能力，不能写成已经通过全天自治或生产运行验收。
