# 研究判断逐项对照开发记录

2026-11-20，承接既有研究判断质量与持续认知更新主线。

## 实际问题与本批行为

真实连续研究第二轮中，部分“保留”只指向更短的新表述。例如旧判断中的团队培训推广、种子用户/PMF验证等交付细节，并没有在所指新判断中完整重申。引用相同原文、话题相似或已有精确轮次回链，都不能证明整条旧判断的含义被保留。这些历史记录不改写。

新调查在修正记录中逐项摘录旧判断，说明每项保留、修订、撤回或未解决的原因，分别连接本轮判断及其原文。只核对了部分内容时，应明确列出其余未复查内容；存在未解决内容，不能将整条标成保留。程序检查引用与对应关系，不声称可以自动判定语义等价或发现全部遗漏。

普通研究回答与工作地图共同采用这项方法。研究提示同时强调：先解释业务问题、任务、交付对象和协作边界，再解释能力与工具；先识别原文章节和修饰范围，再区分一般资格、优先条件及条件化例外。共同技术词不能直接推出相同工作或责任可迁移。

## 主流程中的使用

- 研究对话、单轮报告和整项导出显示逐项内容、对应新判断、理由与依据。
- 旧知识、地图与下游研究的修正提醒带入同一份逐项说明，不自动改写已采纳知识。
- 跨会话追问会取得逐项说明。明确追问旧范围判断时，也保留该判断原有维度、解释性质及资格性质，避免仅带旧文本而丢失原判断口径。
- 未解决项成为可以直接带入追问的问题；问题超过首屏数量仍可展开查看。
- 当前判断、地图受影响状态和待查问题按同一旧判断的最近有效处理整理，历史各次处理仍可回看。这里整理的是最近处理状态，不以时间顺序决定事实真假，也不自动赋予人审状态。
- 旧记录没有逐项对照时，查看与导出明确说明这一限制，不补造历史核对结果。

## 验证与限制

使用独立临时资料验证了：读取原文、提交逐项修正、关闭后重新打开研究、后续追问取得逐项说明、原判断保持原样。针对部分复查、对应依据、界面/导出和后续处理状态做相关本地检查；两个已有界面测试的简化页面对象补齐了已存在页面行为需要的属性。

没有追加真实模型研究，没有修改三轮历史状态、预算或原始材料，没有重启、安装或访问用户运行工作台。源码行为已实现；用户实例尚未更新。真实新模型输出能否稳定完成逐项语义对应仍未验证，不能用本地检查代表研究质量验收。完整目标继续保持进行中。

## 继续补齐：已保存关系的原判断口径

继续检查能力与工作关系的复用路径，发现已保存关系虽然保留完整两端文字、迁移边界及原文，但再次提供给研究Agent时缺少支撑判断的维度、直接/归纳/推断及必备/加分口径。仅凭“关系需要某能力”容易误读为招聘必备条件。

现在沿既有来源研究和判断编号，只读取得原判断的完整文字、要求性质、解释性质及各自引用来源。保存候选前的预览、已保存定义/关系页面和Agent知识检索均可使用；有关联比较时取得双方判断。原资料和已保存知识不迁移、不补写、不新增独立证据。

Agent检索按原研究汇集判断，避免同一判断因多条关系重复提供。上下文放不下时省略整条并给出省略数，不截短强度或限定语。原研究被遗忘后不再读回支撑判断。针对地图保存、复用及遗忘路径和本次展示做了相关检查，未再次扩大到完整发布或保护检查。
