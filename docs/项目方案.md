## 2. 产品目标

Work Observer 是面向个人的 AI 应用与 Agent 岗位资料和研究工具。以真实职位内容为依据，帮助用户：

1. 保存和查找关注的岗位，了解公司、薪资、地点、学历、经验和具体职责。
2. 对比不同岗位的工作任务、交付物、能力与工具要求，而不只比较职位名称。
3. 根据个人条件筛选候选岗位，并明确不符合条件或资料不足的原因。
4. 对岗位集合提出问题，获得带原文依据、样本范围和时间说明的回答。
5. 随真实资料积累，逐步支持历史比较和对工作变化的研究。

初始范围沿用上海、少量 Agent／AI 应用相关关键词及现有 BOSS 数据。采集范围由搜索条件和内容筛选决定，建立公司关联不会顺带采集该公司的 HR、财务等其他岗位。一个公司可以对应多个符合关注范围的岗位。

- 独立 HTTP 详情查询、自动后台更新安全令牌、加密保存及新进程复用曾有真实成功；一个约 32.4 小时前保存的岗位参数样例查询成功。
- 最近补详情时前 5 个请求成功，之后第六个请求返回 code 37；按用户要求分别只重试第六条、尝试第七条，也返回相同错误。来源当前暂停，具体根因尚未确定，见 [职位详情补全记录](职位详情补全记录.md)。
- 30–60 秒是连接器的经验性配置，45 秒是本次执行选择，均不是已核实的 BOSS 官方固定阈值；等待不能保证请求成功。
- 主要账号 Cookie 到期后的免扫码恢复、多天稳定运行，以及所有旧岗位参数的长期有效性，均未通过验收。
- 71 项现有隔离测试此前通过；它们验证工程机制，不替代真实连通或长期稳定性证据。

已有 7 份正文可用于最小检索和比较演示。其余详情缺失不应阻止查看、导入和研究流程开发；界面或输出必须标出资料完整程度，不能编造缺失内容。

## 4. 轻量首版交付范围

以下是首版业务范围，现已在本轮 CLI MVP 中完成实现和适当验收；逐项证据与限制见 [MVP 使用与验收](MVP使用与验收.md)。

| 编号 | 需求 | 最小验收行为 |
| --- | --- | --- |
| R01 | 岗位与公司查看 | 能列出岗位、查看完整原文和公司资料，明确哪些记录仅有摘要、公司身份是否已核实 |
| R02 | 基本筛选 | 按城市、公司、薪资、学历、经验、关键词及资料完整程度筛选；未知属性保留为未知，不默认符合或不符合 |
| R03 | 有限资料获取 | 保留现有有界搜索和详情入口；按需执行，失败可说明，部分成功保留，不能为一次查询无限重试 |
| R04 | 静态资料补充 | 首选一个简单的 JD 文本／JSON 导入入口，记录手动来源与导入时间，并复用去重和归档；链接本身不等于已取得正文 |
| R05 | 简单岗位比较 | 从可用正文比较任务、责任、能力和工具，区分必备、加分及资料缺失；关键判断能定位原文 |
| R06 | SQL 与原文检索 | 确定条件由 SQL 筛选统计；解释性问题检索适合范围内的岗位正文，先用关键词和简单规则，不以检索前几条替代总体统计 |
| R07 | 一个最小研究 Agent | 通过受限工具查询岗位、检索原文、比较和形成回答；调用有数量与时间边界，证据不足时明确说明 |
| R08 | 结果留存 | 用户需要时保存简单研究结果／报告，保留问题、数据范围、所用岗位或版本及原文依据；不先建设完整通知和报告平台 |
| R09 | 时间与来源可信 | 区分发现时间、详情取得时间、来源发布时间、本地处理时间，区分实时响应、缓存、回放和手动资料 |

已先复用 CLI 完成业务闭环，随后在 G5 中增加本地中文页面和必要 HTTP 入口。两种入口共用同一业务实现，不重建数据库；本阶段不开展公网平台或多用户服务。

## 5. 数据与存储要求

### 5.1 沿用现有结构

不重新设计或删除现有已建表。七类业务表加一个兼容执行记录表，共八张物理表：

| 表 | 当前职责与取舍 |
| --- | --- |
| `companies` | 保留公司名称、行业、规模、介绍与来源身份；同名不等于同一主体，来源公司编号缺失时明确未核实 |
| `jobs` | 保存可直接查询的岗位内容和属性、公司关联、完整程度、可靠时间及最近一组岗位访问参数 |
| `job_snapshots` | 保留现有内容版本及去重，不另建重复的 Job Versions 表；同内容复用，不因多次采集复制正文 |
| `job_observations` | **保留轻量版**，记录何时、在哪批／哪条规则下看到了哪个岗位版本，支撑 Agent 的时间范围与证据追溯 |
| `source_documents` | 保留原始响应文件索引，用于核对、纠错、补提取遗漏字段；原始大文件留在本地目录 |
| `watchsets` | 继续保留现有搜索规则及版本，说明数据来自哪些关键词、城市和采集范围，不建设复杂配置系统 |
| `collection_runs` | 保留简要执行条件、数量、成功／部分成功／失败与错误，区分数据没有新增和任务根本没有成功 |
| `task_runs` | 原有兼容执行记录先保留，不在本轮强行合并；暂不扩展成通用调度平台 |

`job_access_contexts` 不单独建表，最近一组 `security_id`、`lid` 等岗位参数放在 `jobs` 内部字段。它们不等于账号登录状态，不作为岗位身份、内容版本或公开展示字段；账号 Cookie、安全令牌继续加密独立保存。

观察表保存的是采样中看到岗位的事实，不能证明岗位持续开放或没出现就已关闭。它不复制完整 JD；Agent 按需查询聚合结果和对应证据，写观察记录不需要调用模型。

### 5.2 时间与状态

- `first_observed_at`：首次收到该岗位资料的时间；可作为“首次发现”口径，不能冒充发布时刻。
- `last_observed_at`、`last_seen_in_search_at`：最近收到资料、最近取得包含该岗位的列表响应；结合响应来源判断新鲜度。
- `detail_collected_at`：该份详情取得时间，不等于网站更新时间。
- `source_published_at`：只有来源明确且可以可靠表达时才填写；目前没有可靠值的记录继续留空，可保留来源时间原文。
- 公司／招聘者活跃时间、首次发现时间均不能替代岗位发布时间。
- 保存来源明确返回的招聘状态及确认时间；静态档案不能宣传为实时状态。搜索缺席、参数失效、网络失败或 code 37 都不等于已关闭。

### 5.3 原始事实与分析分开

原始响应、来源原文、确定性解析、模型分析和人工修正保持可区分。模型判断不能覆盖来源原文，也不能被重复引用成新增独立证据。当前列表和详情缺失值保护、唯一身份约束、真实与回放隔离继续有效。

## 6. 招聘连接与认证边界

- MCP 是工具入口，HTTP 是连接实现的一部分，二者可以共存。固定采集流程可以直接复用底层连接器能力，不要求所有业务必须经 MCP。
- 保留现有 MCP 与已经可复用的连接器代码；对原始响应做统一归档和业务字段转换，不同时维护两套独立业务数据。
- 独立 HTTP 详情路径有成功证据；HTTP 列表、长期认证及全量旧岗位复查尚无完整验收，不得将局部成功写成所有能力已具备。
- 接受程序短暂启动后台浏览器准备有效资料，不要求模型逐个点击页面，也不为每个岗位重复启动浏览器。
- 同一账号的操作遵守共享预算与明确停止条件；不以重复清除暂停、持续刷新或切换入口绕过风险停止。
- 本次不继续线上排查 code 37，不恢复暂停、不发新的岗位请求。未来需要联网时，以明确授权的有限采集目标执行，记录真实结果。
- 参数过期或不能复查旧岗位时，已经取得的静态正文仍可使用。手动资料入口和本地研究功能必须能独立工作。

## 7. Agent、SQL、RAG 与记忆

保留“**一个研究 Agent 配合固定业务流程，SQL 与 RAG 协作**”的架构方向。

- 采集、校验、去重、保存和确定性统计由普通程序完成，不让模型代替数据库操作或逐条浏览网页。
- 研究 Agent 先用 SQL 确定候选岗位和样本范围，再检索原文，以少量必要片段支撑解释和比较；不能每次把整库内容塞入上下文。
- 首版 RAG 从 SQL 过滤、关键词与原文引用做起。向量数据库、嵌入、重排均由后续实际检索效果决定，不作为首版必装条件。
- 输出说明资料范围、采集时间、完整详情数量和信息缺口。当前少量、部分缺失的样本不足以直接推出全市场趋势。
- 业务知识、偏好与长期记忆仍归业务库；需要跨研究留存时再按实际写入需求增量设计，不预建整套空表。
- 研究检查点与业务事实分开。复杂长任务恢复、LangGraph 全量持久化及通用 worker 不作为最小问答闭环的先决条件。

## 10. 首版验收与当前交付边界

轻量首版的应用验收以已有静态数据或明确来源的手动数据完成：能查看和筛选岗位、看到原文和时间、完成一次可回溯的比较或问答，并保存需要的结果。模拟材料只验证机制，不能声称为新增真实岗位或实际市场变化。

后续已获授权实施的交付包括 CLI 筛选、人工补录、原文检索、单研究 Agent、比较及按需保存文件。复用既有依赖和表，未迁移正式库、未访问招聘源、未修改认证资料或暂停状态；少量真实模型调用用于当前验收。模型失败与离线证据包明确区分，定时和前端仍未实现。
