# 业务研究评测协议与验收

2026-11-19，0.7。本协议补充真实研究的语义评测证据，不执行研究、不调用模型、不启用候选。原检索词面题与逐run审核继续保留，二者不能替代先锁业务问题、再登记实际结果的协议。

## 最小闭环

`ResearchBenchmarkService(store, repository)`先锁定任务问题、岗位范围、逐项完成条件、开发/预留分区、每题调用和耗时上限，以及baseline/candidate实际方法SHA与版本。可进一步锁策略和上下文SHA；程序从权威run与checkpoint核验，调用者自报arm不能替代核验。首版仅接`research`结果，完整画像需另用画像审核服务；base research不能冒充包含领域和面试问题的完整画像。

随后显式开启一次分区尝试，为每题两臂各保留唯一槽位，再登记终态权威run。登记只保存run引用、结果摘要、方法和上下文摘要、原始来源范围摘要、实际调用/时间/token、结构化问题，不复制整份结果。运行早于槽位只允许明确声明的开发回顾；预留题即使晚于锁题，仍须晚于该次槽位预留。失败、未完成、超预算、错误方法、引用不符和重复结果均占用槽位并保留；缺失执行必须在封卷时明确记为`not_run`，不能悄悄删题。

封卷产生随机匿名包。包只含任务、完成条件、声明预算、冻结正文、逐claim与引用、未知缺口及机械问题；不含arm、run、方法、实际用量、旧评分或其他审核。审核者必须逐条填写引用支持与性质，并覆盖全部完成条件及六维：引用语义、要求分类、覆盖、未知处理、反例、是否回答。`profile_coverage`为沿用的维度键，在这里指锁定任务的业务覆盖，非完整画像审核。所有包均有审核后才能关闭；关闭后才可看解盲配对，也不能再追加或修改审核。

封评前同一来源类型、同一规范化声明名（Unicode兼容规范、大小写和空白统一）的审核者可以修正评分。修正追加新历史，重复保存相同最新评分保持幂等；配对仅使用每位声明者最新评分，不把其旧未知当另一人分歧，也不重复计算人数。真正不同声明者评分相反仍标冲突，不能挑高分。全部历史ID在封评时锁定。每包最多5位声明者、50条历史；姓名分组不等于身份核验，改用另一名字仍只能靠诚实声明约束，不能称程序证明了独立人审。

人工、Agent辅助、独立性与盲法声明分别保存。程序无法证明操作者真是人类、未参与开发或此前没见过结果；本机接口没有身份认证，不是可信第三方裁判。隐藏元数据也不能消除写作风格或审核者历史接触造成的识别。Agent操作必须用`agent_assisted`；未知不得自动算通过。

配对逐题显示支持/不支持/未知、性质错误、遗漏/未知完成条件、回答与六维评级、方法及实际预算。调用与token只记权威记录；未提供的费用保留未知。任务预算不替代原项目/工作流累计预算，也不重置历史额度。相同方法仅换标签/版本文字/个人上下文、或复用同一结果，报告`no_demonstrated_change`。不同真实方法仍不代表已证明收益。

## 上下文与预留边界

上下文摘要从checkpoint历史第一条`role=user`的JSON读取完整`project_context`与`memory_context`，包含真实goal、完成条件、refresh纠错说明及先前claim；只持久保存摘要。`memory_refs`、`knowledge_refs`、parent与project ID另用于依赖审计，不能证明实际输入相同。缺少可解析历史标`reference_only/context_unverifiable`。未预先锁定却发生的策略/上下文变化标为混杂；配对不自动宣称严格单变量。

每题范围与正文SHA固定。题号变化不能洗掉旧题：规范化问题与来源集合的指纹跨协议及遗忘后的ID摘要保留，检测完全相同问题范围；语义改写是否复用仍依赖真实声明，程序无法证明。外部预注册文件摘要只记录来源，不能倒填本协议锁定时间。开发已暴露语料、回顾登记、复用题均显式保留。当前7份旧语料均已被开发者阅读，未来相同语料任务预留最多称“同语料任务留出”，不能称未见公司泛化或全市场代表。

固定验收门槛包括至少2道预留题、独立人工任务声明、每包独立盲审人工声明、无复用/混杂/来源或预算失败，以及候选完成题数至少增加1。未满足即`insufficient`或`rejected`，不得用Agent评分激活。`accepted_in_frozen_scope`也仅是本协议的有声明局限的有限语料评测结果；本服务没有任何自动应用入口。测试中的human字段是明确标注synthetic的测试actor，不是真实人审证据。

## 本机入口

独立CLI不依赖主产品命令。协议JSON字段见`ResearchTask`、`MethodArm`，以及`preregister`参数。先由任务作者提供任务和完成条件；开发者只取开发任务，服务没有读取全部预留题的公共方法。

```powershell
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db preregister protocol.private.json
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db development-tasks BENCHMARK_ID
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db open BENCHMARK_ID development
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db register BENCHMARK_ID TASK_ID baseline REAL_RUN_ID
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db register BENCHMARK_ID TASK_ID candidate REAL_RUN_ID
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db seal BENCHMARK_ID development
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db packet BENCHMARK_ID OPAQUE_PACKET_ID
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db review BENCHMARK_ID OPAQUE_PACKET_ID review.private.json
uv run --locked python -m work_observer.quality.research_benchmark_cli --db data/isolated/app.db close BENCHMARK_ID development
```

结果默认保存在checkpoint namespace的4张`(namespace,id,record)`表：`research_benchmarks`、`research_benchmark_submissions`、`research_benchmark_rounds`、`research_benchmark_reviews`。来源工件固定为`db.parent/research-benchmarks/<32hex id>/corpus/{corpus.db,manifest.json}`，仅包含来源表、无个人记忆或访问上下文；冻结正文仍属本机私有材料，不提交仓库。主产品完整备份/恢复需同时覆盖这4表和固定工件字节，缺失/损坏来源拒绝继续，不重写SHA。服务不接受网页传入任意工件路径。

`invalidate(run_ids=(), project_ids=(), memory_ids=())`返回`invalidated_research_benchmark_ids`。命中依赖即擦除整协议问题/完成条件/自由评语及其提交、封卷和审核记录，只保留ID、依赖与防复用摘要，重复调用仍能找回同记录，不能恢复旧审核。原始岗位来源按现有来源保留策略管理。显式`packet --output`或外部手工保存的材料是另行导出副本，须由操作者独立保管和删除，不能宣称遗忘已自动清除外部副本。

## 当前真实开发演示

已将既有两份真实research输出登记为1道明确回顾、复用且语料已暴露的开发任务：两臂各13条判断，实际8次/74.479秒与5次/30.614秒；token分别89490与43088，费用未知。权威原run记录前后摘要一致，无新增模型调用，未改正式库或旧结果。

已知两臂身份的Agent离线逐条复核得到：baseline 13支持、candidate 11支持与2条来源层未知；未发现当前两份最终结果存在必备/优先混标。历史纠错trace的问题不能自动等同于最终结果仍遗漏整条，须核对终稿。候选在正文引用中夹带公司描述，仍需核对scope元数据与正文的来源层。此统计只是Agent辅助审核意见，不是人类金标准。两次实际输入的纠错上下文摘要不同；协议未事先锁住该差异。配对为`insufficient`，人工审核不完整、混杂为真、未启用候选。私有协议和逐条记录只存隔离演示目录与checkpoint，不公开原文。

专项覆盖锁题/一次预留、终态失败和预算、假引用、同方法换标签、重复题号、真实输入上下文变化、历史缺失、绑定后篡改、人工分歧、Agent不可冒充人审、画像拒绝和遗忘清除。合成测试验证机制，不能代替真实质量或真实独立人审。
