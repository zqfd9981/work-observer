# 0.5 持久研究、知识与真实质量阶段

2026-11-19。0.5.0仍是单用户本地Alpha。下面区分实现、隔离验证、真实任务证据及未验收事项，不以接口、表或测试数量判断成熟。

## 已可操作的闭环

“持续研究项目”保存目标、明确岗位范围和范围版本。支持追问、澄清、改目标/范围、调查、反例和审核后汇总。研究项目属于本产品，不读取Codex聊天历史。历史只挑选同范围、仍有效的相关认识；每次最多3个既往研究、14,000字符，显示遗漏判断数和原运行回链。短判断在预算内完整保留，不能固定取前4条。

每步有问题、完成条件、依赖、原文范围、调用和时间上限。默认项目36次模型调用、900秒、6轮、4次公开请求；硬上限分别72、1800、12、8。单轮仍至多12调用、300秒，公开搜索/全文各至多2次。先预留整轮额度，中断沿用原轮检查点、正文版本、调用次数和已耗时间。重启只恢复状态，不自动花费。

默认计划包含调查、主动反例与人审后汇总。模型可为具体缺口提出最多两个带完成条件和证据要求的补查；执行器按剩余项目额度和轮数去重安排。每次页面“继续”最多执行3步。独立`research-worker --once`可从持久队列串行领取，每批最多6步/36调用/900秒/4公开请求，领取原子校验项目和整批额度；不是仅API进程任务。详见[持久调查队列](持久调查队列执行.md)。等待资料、人审、预算不足时停止并释放执行器，没有子任务等待自己的死锁。模型完成进入待核对；离线证据包不能被标成完成模型调查。

用户明确偏好、人工纠正、经核对知识、待验证假设和研究方法经验分开保存。范围为全局/项目/岗位，支持主体、有效期、冲突、版本、撤回和遗忘。同一主体的重叠有效期不同值暂停召回，须明确选择。模型只能提出有原文/实际工具行动回链的假设和方法候选，不自动改偏好、启用方法或证明效果；候选重复执行幂等，撤回后同次执行不会重新造候选。详见[分层记忆](分层记忆使用与验收.md)。

统一检索包括岗位当前/历史正文、启动时冻结的公开正文和有效派生知识。派生知识、领域定义和关系只作线索，关键判断须重读原文；公开企业背景不能单独证明岗位任务。当前范围、历史截止和别名策略均冻结。每URL默认最新公开版本，范围超限明示；每来源先提供代表片段，防长官网挤掉全部短JD。领域定义、任务/交付物/责任/能力/工具关系、反例及合并/拆分都先审核；旧定义人工纠正不静默映射新版本。详见[统一证据与领域知识](统一证据与领域知识验收.md)。

“领域变化观察”显式冻结两次完整样本面板，分开原文/字段、样本增删、分析/分类方法和有效性变化。未知画像、未知领域和缺正文不按零要求处理；字面统计不当作必备比例。个人影响只解释明确条件；文本偏好不自动变成硬性条件。待核对问题可幂等建立研究项目，保存不执行模型。详见[领域观察](领域观察与个人目标影响验收.md)。

“资料核对”只提出跨入口疑似重复；审核关联保留两个岗位、不同字段与全部历史，不自动改变统计分母。截图精确引用保存原图SHA、人工bbox、正文版本/字符范围及逐字引用。坐标明确是人工核对，不冒称OCR检测。详见[资料核对](资料核对与截图区域引用.md)。

## 遗忘与恢复

个人记忆遗忘和整项目遗忘共用依赖闭包，清理关联研究、跨项目续接、派生记忆、关系、画像、业务审核、观察面板、通知和当前报告目录。原JD和图片保留。只存ID和目录指纹的擦除日志支持中断后自动续清；完成日志不重复执行。未完成时拒绝返回派生内容，读取期间发生遗忘也拒绝返回已读快照。

擦除绑定报告目录；用错目录失败关闭，不能把“在错误目录没有文件”当作完成。备份只包含目标库命名空间；恢复到新目录会重定位命名空间、原文路径和擦除目录指纹。独立下载副本与旧备份不自动擦除。来源键在恢复后仍保持项目幂等，不重复造项目、步骤或预算。

## 实际验证

隔离验证覆盖多轮/重启、改偏好后排除旧认识、范围修订不外推、冲突选择、过期和源失效、公共正文混入防护、关系撤回阻止恢复、同源写保护、CLI实际执行、跨进程领取互斥、半途计划重建、备份恢复和擦除失败续清。这些证明机制，不证明开放业务语义正确。

本轮少量真实模型共20次调用：最初两轮各5次，跨进程重开后完成续接；随后同一冻结问题/岗位/正文做两次修复复验，各5次。所有结果留在隔离资料库，未写正式业务表。没有新增招聘请求；公开资料验证复用已归档官网正文，未恢复BOSS。

独立Agent逐原文审核发现并保留了真实缺陷：任职资格性质跨轮漂移、一条跨岗比较缺少另一侧引用、固定截前4条遗漏重要旧判断。修复统一要求口径、双侧引用说明与相关上下文选择后，后续复验仍发现混合必备/加分，以及业务库身份元数据不能由JD逐字引用支持的问题。最后12条中11条有原文支持，1条来源层次仍待核对；此为`agent_assisted/pending`，不是人工验收通过或语义正确率。新增的词面拆分护栏和元数据提示不代替语义审核。

真实检索基线冻结15岗位、7正文、8缺正文，4开发题+4预留题。原文锚点为Agent辅助草案，待独立人工标注；结果保持证据不足，没有自动启用候选。被查看过的预留题不能继续冒充全新验收集。详见[质量基线](真实研究质量基线.md)。

实际浏览器已验证离线项目/追问、偏好冲突选择、统一检索、领域候选审核、两个合成入口关联、截图字符6–26与人工框回查、观察报告到项目衔接。新页面加载完成后在390px手机宽度未出现整页横向溢出。合成资料清楚标明，不作为真实市场证据。

## 操作

页面启动仍是`uv run --locked work-observer serve`，打开持续研究项目、领域与证据、研究质量核对、资料核对及领域变化观察。

CLI结构化输入用`--file`，项目操作为`product projects create|get|ask|revise|review|run|forget`；新业务入口为`product unified run`、`product domains`、`product relations`、`product domain-collection`、`product data-quality`、`product quality`、`product updates`。同一服务实现不在CLI重写业务规则。自定义报告目录统一传`--reports-dir`，防遗忘恢复误用路径。

真实逐判断待审样例位于隔离库，查看命令：

```powershell
uv run --locked work-observer serve --db data/project-verification/app.db --reports-dir data/project-verification/reports --port 8769
```

打开`http://127.0.0.1:8769/#quality`，逐条检查原文、要求性质、遗漏、未知、反例与是否回答问题。Agent辅助评审不能选择人工批准；引用存在或执行结束不会显示业务质量已通过。

## 仍未达到的成熟条件

独立人工语义标签和更广的新验收样本仍缺失，真实任务成功率、研究方法改进的接受/限量应用和退化回退实绩尚未成立。当前可运行的真实配对与审核机制，不等于已经形成可靠的自我改进能力。

领域定义与关系已经可演进，但真实跨企业知识尚待人审积累；长时间研究优先级、跨日资料到达后的实际自动接续和长期运行质量仍需持续实际使用。两次重复静态观察不提供真实趋势。招聘恢复、多日无人采集以及容器/目标部署各自需单独验证，不能由本轮代码和隔离测试替代。
