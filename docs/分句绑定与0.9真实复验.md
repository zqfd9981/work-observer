# 0.9 分句绑定与真实开发复验

2026-11-19，单用户本地Alpha。Goal仍在进行，默认仍是research-method-v5-responsibility-boundaries。来源分项候选没有获准替换默认方法；没有恢复招聘、公开发布或推送。工程检查、结构通过和Agent辅助评语均不能冒充独立人类验收。

## 修改与保留的边界

0.8两份未完研究的拒绝原因包括合法未知表述的错误标签、过宽的来源并集以及真正的跨侧引用遗漏。不能把全部拒绝当作语义纠错收益。0.9先做source-first-v2的三题开发复验，再做source-first-v3的单题事后跟进；两个阶段的运行、实现摘要、原始提案和封评分别保留。

当前v3区分岗位承担者、人工操作角色、团队、系统与Agent；“独立排障”等子任务和端到端负责程度分别登记，团队协作与人工接管也分别登记。已有分句ID保持稳定，增加原文单元及完整阅读/完整展示信息。正文因长度切成片段时，终稿引用必须覆盖完整单元，不能以截断前缀省去后半句的资格限定。岗位、快照、文档及内容摘要须与实际已读正文一致。

每条自由判断显式选择finding及其分句子集，再由已读来源导出引用，不让模型另造不一致的证据ID。未知分项单独展示，不能充当自由肯定或排除判断的支持；所有活动未知仍展示，不由模型挑选隐藏。主体或维度修正用新ID、supersedes及理由保留旧记录，不能暗改原文、性质或自由判断。工具调用、修正与失败仍消耗原额度，没有隐藏审核模型或预算重置。

多岗位的直接原文明示判断不能混写；跨材料归纳或推断允许连接不同业务维度，并逐侧显示主体和维度，明确提示“多维分析不表示同口径单维可比”。这只是取消过度严格的内部结构拒绝，不改变外部任务完成条件，不自动判定语义正确。普通报告、Markdown、质量包和匿名包保留精确分句、上下文、主体及修订历史；空终稿不输出失败草稿遗留的分析提示。

这些规则仍不能保证分项语义正确。真实跟进中仍有把“独立排障”标成端到端能力、把带后缀资格的前缀登记成原文明示的问题；最终完整单元检查阻止了后者作为终稿发表，但草稿分项本身仍可能错误，必须标“语义待核”。

## 匿名审核的证据限制与修复

新的独立开发Agent只收到六份匿名包，核对86条终稿判断、63分项及36条完成条件。原始意见为61支持、23不支持、2未知；资格分类3条错误，完成条件22满足、14遗漏，六维审核14通过、22失败。封评业务满足标准1题、候选0题，整体insufficient。

审核同时发现旧包只有正文及标题，遗漏模型实际看过的冻结公司标识，影响其中两份包的公司名称相关意见。原评语和原匿名包未改，不把23条“不支持”全部计成模型错误，也不计算61/86准确率或据此作公平总体排名。另有不依赖该缺陷的资格强度漂移、将方向选择当独立任务、遗漏招聘方核实问题和案例准备等问题。审核只是Agent辅助，不是独立人类批准。

新预注册协议显式锁packet_context_version=2，从冻结corpus.db只读取得岗位标题、原始公司名、身份核验状态与快照，单列scope_context。页面说明这些是冻结岗位标识，不是JD逐字业务声明，不证明组织隶属、公司整体业务或当前仍在招。只输出白名单字段，标准包即使没有分项也可展示该上下文，不泄露方法臂、摘要或旧评分。普通质量包仍保留其历史run.scope，不能混称为新冻结语料上下文。

旧协议缺版本仍按1读取，原字节、hash与评语保持；不能事后给旧包补公司名后追认通过。v2三题使用上下文版本1，v3单题使用版本2。v3有实际候选包和明确未运行的标准槽位，后者只做单独标注的机械未知核对；两者不能组成新的独立语义配对证明。两个新轮均封评insufficient，原0.8封评也保留。
