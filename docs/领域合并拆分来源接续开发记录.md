# 领域合并拆分来源接续开发记录

## 实际问题

研究地图保存的工作类型带有来源研究、原判断下标、岗位/归档范围及项目范围。手工合并、拆分会保存关联定义编号，但新定义没有直接的单一来源；原读取路径因此将其当作未限定来源的通用定义。隔离复现中，项目内的两个类型先合并再拆分后，能够在通用范围召回，原判断与后续纠正也未沿用。

## 修复

沿现有合并、拆分和前一版链接解析来源，不添加表或改写旧记录。有明确新研究来源的版本使用该轮依据；没有新来源的合并/拆分及其手工改写沿用原定义的各份来源，普通手工定义仍保持原行为。

- 研究复用、统一检索、画像分类和依赖检查核对全部来源的项目、岗位、归档及有效性。下游摘要继续传递这些约束，不因中间合并记录没有单一 `run_id` 而失去范围。
- 统一检索按来源研究汇集双方完整支撑判断；重叠判断和同一后续纠正去重，不重复计作独立证据。沿用的来源上下文计入现有展示额度。
- 来源研究的后续修订、撤回或疑问继续提示；任一来源失效时停止默认复用，既有遗忘闭包仍清除合并/拆分及消费者的派生文本，原始资料保持。
- 页面按各来源的项目范围筛选，并展示原研究链接和沿用说明；原文不自动证明当前合并后全部表述正确，仍需语义核对。

## 验证及边界

先复现通用召回越出项目范围，再修复。新增隔离检查覆盖合并→拆分→原范围复用、两份不同来源及后续改写、原判断与后续纠正、直接和间接消费者的范围、来源失效及个人背景遗忘后清除。核对原研究和原始岗位未被改写。页面回放覆盖项目筛选、双方研究链接、支撑判断与文本转义。
