# Work Observer 招聘市场与职业演化研究

> 2026-11-18 最新授权：正在从已完成的 MVP/G5 继续建设完整、可部署与可展示的 Agent 产品。持续研究只是其中一阶段；完整需求、缺口及验收状态统一见 [完整产品验收台账](完整产品验收清单.md)。下文各阶段历史取舍不再构成本次完整产品授权的永久排除项；尚未验收的能力不会列为完成。招聘来源继续暂停，实际公网发布尚未开展。

Work Observer 以招聘信息为主要证据，持续研究市场上的工作种类、职责结构和能力要求如何变化，并帮助个人理解这些变化对自己的意义。项目同时提供岗位筛选与求职准备支持。

重点梳理的关系是：**企业的业务背景与目标 → 需要完成的任务和交付物 → 承担任务的岗位 → 所需能力与使用工具，以及这些关系的持续演进。**

当前已完成 **轻量 MVP（R01–R09）与 G5 本地操作页面**：岗位与公司筛选、人工 JD 补录、原文依据、一个受限研究 Agent、岗位比较及结果保存可通过浏览器操作，原有 CLI 保留。没有引入定时任务或公网服务。

**最新进度（2026 年 11 月 18 日）**：已按用户授权以 Goal 模式完成实施。正式库仍为 15 个岗位、7 份完整正文、8 个缺详情；招聘源继续暂停。本轮两个真实模型研究均完成，人工补录在独立副本验证，原库全部记录与暂停文件保持不变。范围以 [项目方案](项目方案.md) 为准，实际入口和验收见 [MVP 使用与验收](MVP使用与验收.md)。

随后 G5 已完成本地页面：**107 项测试通过**，Ruff、格式、JavaScript 语法与依赖检查通过；浏览器真实比较使用 5 次模型调用形成 12 条带引用判断，保存、再次查看、原文核对与独立副本上的重复补录均已试用。正式库仍保持原记录，见 [G5 页面验收](本地页面使用与验收.md)。

## 立即使用

推荐直接打开本地页面。在项目根目录运行：

```powershell
uv sync --locked
uv run --locked work-observer serve
```

浏览器访问 **http://127.0.0.1:8765**，即可查看资料、勾选岗位比较、粘贴或读取文件补录、保存和再次查看研究。终端保持运行，按 `Ctrl+C` 停止。详细步骤与限制见 [本地页面使用与验收](本地页面使用与验收.md)。已有库无需初始化或迁移，来源暂停状态继续保留。

在项目根目录运行（PowerShell），复用已有 `.env` 与数据库：

```powershell
$env:PYTHONUTF8 = "1"
uv sync --locked
uv run --locked work-observer jobs --city 上海 --detail detail
uv run --locked work-observer jobs --salary-min 20000 --salary-unit month
uv run --locked work-observer companies
uv run --locked work-observer search --term Python --term RAG
uv run --locked work-observer research --question "这些岗位的任务、能力与工具要求有何不同？" --detail detail --save
uv run --locked work-observer reports
```

查询返回内部 ID 后，可运行 `job --id <内部岗位ID>`、`company --id <内部公司ID>`、`source --id <文档ID>` 核对完整资料。用 `compare --job-id <岗位A> --job-id <岗位B> --save` 比较指定岗位。`report --id <report_id>` 再次查看，无需调用模型。

人工补录：`uv run --locked work-observer import-jd --file C:\资料\我的JD.txt --title "实际岗位名称" --company "实际公司名称" --external-id my-jd-001`。JSON 格式、关联已有岗位和去重规则见 [使用说明](MVP使用与验收.md)。手动资料单独标明来源，不覆盖平台原文。

无模型配置时给研究命令加 `--offline`，只生成证据包，明确标为未执行模型分析。研究默认最多 10 次调用、180 秒、20 个候选；保存结果包含问题、范围、岗位版本和原文引用，位于本地 `reports/`。所有原始资料、模型密钥及生成结果均不提交到公开仓库。

筛选输出 `counts` 是分页前的总体计数，`jobs` 同时列出 `matched` 与条件 `unknown`，不能把未知当作符合。学历、经验按原文字面筛选；薪资仅比较 CNY 相同周期的区间。`source-status` 只读本地暂停状态，当前 `collect` 会在发出请求前明确停止。

## 项目目标与第一版范围

第一版先面向国内 AI 应用与 Agent 相关岗位，接入一个招聘来源，从一个城市与有限关键词开始。观察范围需要记录和版本化，样本结果不能直接代表全国市场。

轻量首版已获授权并完成以下业务结果：

1. 在现有岗位与公司库中查看、筛选和定位原文，明确摘要／完整详情及时间缺口。
2. 保留有限采集，补一个简单 JD 文本／JSON 导入入口；来源不稳定时，静态资料仍可使用。
3. 先以 SQL 与关键词检索提供数据和证据，再用一个最小研究 Agent 比较任务、能力与工具要求。
4. 用户需要时保存带来源的简单研究结果，不先建设完整报告、通知、调度和自改平台。

定时、全量在线复查、主要账号登录到期后的自动恢复、复杂记忆与自我改进均后置。用户随后授权的 G5 已交付本地页面和薄 HTTP 服务；公网部署、多用户系统未开展。自动投递、联系招聘者、简历编辑及跨平台全市场采集不在本首版范围。

## 已确定的架构方向

- **一个研究 Agent 配合固定业务流程。**程序承担采集、去重、存储和统计；Agent 根据证据决定调查路径，不只在流程末尾写报告。
- **SQL 与 RAG 配合。**确定的筛选和统计使用 SQL；解释性研究检索原文、历史和相关资料，组成证据包交给模型。首版先做范围过滤、标签、别名与关键词检索，向量检索按评测结果扩展。
- **业务数据与记忆有明确归属。**岗位、知识、偏好和人工纠正保存在业务库，摘要关联权威记录；研究线程检查点单独保存。
- **研究输出有据可查。**首版先把原文引用和样本口径做好；完整的策略实验、发布与回退留在长期规划，不要求当前一次实现。
- **单机、有界、复用已有实现。**先用简单业务入口，不先搭通用常驻 worker 或多 Agent 平台；复杂长任务确有需要时再补恢复机制。

继续使用现有 Python／uv、Pydantic、SQLite／SQLAlchemy、Alembic、MCP 客户端、HTTP 适配及 Typer。LangGraph、FastAPI 等按具体目标的实际需要再引入，不将全套框架作为轻量首版前提；不改 Go 语言，不重写已有工程。

## M1 运行与查询

在项目根目录运行，沿用 M0 的本地连接配置：

```powershell
$env:PYTHONUTF8 = "1"
uv sync --locked
uv run --locked work-observer db-init
uv run --locked work-observer collect --watchset ai-dev
uv run --locked work-observer db-stats
uv run --locked work-observer runs
uv run --locked work-observer jobs
uv run --locked work-observer job --id <jobs返回的内部ID>
uv run --locked work-observer history --job-id <jobs返回的内部ID>
```

`configs/watchsets.toml` 中 `ai-dev` 默认搜索上海 `Agent`，最多 1 页、前 2 个唯一岗位的详情、3 次业务调用尝试。达到取样预算不继续翻页，结果会标记覆盖有限，不称为全市场数据。相同观察配置复用版本，配置修改会绑定新版本；当前只支持单次手动运行。

业务数据库默认 `data/app.db`，原始响应在 `data/raw/m1/`。同来源岗位 ID 匹配同一岗位；相同内容复用快照，每次运行分别保存观察与来源引用。列表和详情分开，不用详情空值覆盖列表字段。失败和需要恢复认证返回非零退出码，失败页数量记为未知，不伪装成零岗位。

用本机已有的 M0 真实资料验证归档，可在**独立回放库**重复执行以下回放命令：

```powershell
uv run --locked work-observer db-init --db data/replay.db
uv run --locked work-observer replay-m0 --bundle data/raw/m0/20261117T090846Z_57ff5988 --db data/replay.db
uv run --locked work-observer db-stats --db data/replay.db
```

回放检查原文件指纹并保留 M0 采集时间，记录为 `mode=replay`，不产生平台请求、不构造未保存的页或详情。实时与回放不能混用同一数据库；pytest 模拟数据仅进入测试临时目录。当前机器实际回放验收库为 `data/m1-replay-verification.db`。以上数据、认证配置和验证结果均被 Git 忽略。

## M0 运行方法

在项目根目录运行（PowerShell）：

```powershell
$env:PYTHONUTF8 = "1"
uv sync --locked
uv run --locked work-observer --help
uv run --locked work-observer mcp-tools
uv run --locked work-observer doctor --error-probe
```

当前机器已生成被 Git 忽略的 `configs/mcp.local.toml` 和 `.env`。新机器首次配置时，从 `configs/mcp.example.toml` 与 `.env.example` 复制到对应本地文件，按实际安装路径和服务配置填写；不要覆盖已有本地配置。

- 招聘：复用现有 `boss-mcp.exe`、`boss.exe` 和其专用会话。以下 M0 说明属于历史验证方法；当前本地风险暂停，不要通过重新登录、清锁或切换入口恢复请求。静态查询、导入与研究无需招聘认证，来源恢复另定范围。
- 模型：配置 `WO_MODEL_BASE_URL`、`WO_MODEL_NAME`、`WO_MODEL_API_KEY`。默认使用官方 Responses 接口；兼容服务可设置 `WO_MODEL_API=chat-completions`。建议起步型号 `gpt-6-luna`，模型权限和额度以实际调用为准，聊天订阅不直接作为 API 已配置的证据。
- 搜索：`WO_SEARCH_PROVIDER=openai` 复用上述模型配置，实际调用 Responses 的 `web_search`；`WO_SEARCH_PROVIDER=tavily` 时另需 `TAVILY_API_KEY`。OpenAI 搜索也会产生 API 和工具调用费用。
- 密钥只放 `.env` 或环境变量；环境变量优先。命令不显示密钥、招聘者姓名、岗位访问标识或来源错误全文，第三方 MCP 进程日志不转发。原始响应、调用参数及检查报告只保存在 `data/raw/m0/`，包含平台访问标识和个人信息，不对外分发。

可以单独复查，不必重复调用其他已通过的服务：

```powershell
uv run --locked work-observer doctor --only recruitment --details 2
uv run --locked work-observer doctor --only model
uv run --locked work-observer doctor --only search
```

招聘只请求第 1 页，详情数限定 1–3；不会投递、打招呼或联系任何人。模型检查最多两次请求，分别验证结构化输出与工具调用；搜索检查一次请求。`--error-probe` 额外调用一次缺少必填参数的详情工具，在服务参数层验证错误，不编造岗位或模拟成功。

每次检查生成独立目录：完整 MCP 响应、HTTP 响应体、请求（无认证头）、文件 SHA-256 和 `report.json`。`passed` 必须具备实际有效响应；缺少配置、空列表、缺失 JD、身份不一致或失败均不能算通过，退出码为 1。`mcp-tools` 仅表示发现成功，不能替代岗位验收。单项检查只覆盖该项，报告的 `m0_accepted` 仅在一次完整检查全部通过时为 `true`。MCP 的远程 HTTP/SSE 配置与兼容模型接口保留为可选路径，本次真实验证仅覆盖本机 stdio 和官方 OpenAI Responses。
