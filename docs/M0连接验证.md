浏览器必须保持打开，电脑、网络及相应 Windows 用户会话需要可用；本次没有证明注销、锁屏、重启或浏览器关闭后仍能无人值守运行。连接器自身有请求间隔及共享请求预算，本机诊断显示请求间隔下限 30 秒；程序不绕过或修改。遇到认证、浏览器不可用、预算或平台风险错误即停止当前验证，不自动重试。诊断记录未证明保存的 Cookie 持续有效。

### 实际错误结构

业务失败会出现在 JSON 信封 `error` 中，例如上述浏览器会话错误，需读取 `code`、`recoverable`、`recovery_action`，与空结果区分。

另有一类是协议错误：独立调用 `boss_detail` 且省略 `security_id`，服务返回 JSON-RPC `code=0, message="'security_id'", data=null`。这是本机实现观察到的非标准参数错误，不是 `-32602`，也没有业务信封；客户端捕获 `McpError` 并保留错误响应。这次故意缺参检查没有构造虚假岗位，也不验证平台认证失效或限流；后两者没有人为触发。

## 模型与公开搜索

模型使用官方 OpenAI Responses API、`gpt-6-luna`、低推理强度。真实记录 `data/raw/m0/20261117T090256Z_12edfe8f/`：一次严格 JSON Schema 中文输出、一次指定函数调用均成功。工具调用检查只检查模型生成的调用参数，没有执行模型要求的外部操作。真实调用成功证明该 Key 当时可用，不代表已查询账户余额或获得无限额度，也不代表已通过后续语义质量评测。

OpenAI Key 只在被忽略的 `.env` 或环境变量中，HTTP 认证头不进入保存的请求。日志不显示 Key，报告不含来源错误全文。本地原始资料包含平台访问上下文和联系人信息，不能提交或公开分发；认证字段及已知密钥在保存前脱敏，岗位业务字段不做归一化或补造。

方案原定 Tavily Search；M0 为复用现有模型账号，实际采用 **OpenAI Responses `web_search`**，无须再创建 Tavily 账号。提供方由 `WO_SEARCH_PROVIDER` 明确选择，没有静默切换；Tavily 接口保留，但未配置 Key，尚未真实验证。这个调整只改变公开搜索适配器，不改变一个研究 Agent、固定业务流程、SQL 与 RAG 配合、业务知识和长期记忆归业务库、研究检查点单独管理的架构。

首次宽泛搜索响应虽为 HTTP 200、总体 `status=completed`，但出现两个搜索项且其中一个状态为 `searching`，不符合一次已完成搜索的限制，因此探针判失败并保留原始记录。将连通检查收敛为一次明确的官网搜索后，成功记录为 `data/raw/m0/20261117T090800Z_20a2a71f/`，随后完整检查再次通过。程序没有降低成功标准来接纳不完整或超过调用数的返回。

模型与搜索请求均有超时和调用上限；不自动重试认证、额度或参数失败。搜索成功必须存在真实完成的 `web_search_call`、来源 URL 和引用，单纯模型声称“已搜索”不算通过。搜索结果不等同于完整网页正文，正文归档仍属于后续阶段。

### 用户补充的无人操作要求

后续定时任务不能依赖用户事先打开浏览器、反复收集或导入登录态、输入 `SAVE`，也不能把需要人工验证码当作日常正常流程。当前完整检查的 `m0_accepted=true` 仅记录原定三项连接验收通过，不证明这一补充要求已满足。

再次核对本机源码发现，`platforms/factory.py` 在 `fixed_browser_session=true` 时直接构造 `FixedBossClient`，其浏览器连接代码明确不启动浏览器、不自行导航、不刷新令牌。因此目前的人工前置条件来自已有连接器的本机定制逻辑，并不是 MCP 协议本身的要求，单加一个定时任务无法解决。

上游提供自动浏览器及 `httpx-only` 等其他方式，但存在这些方式不代表当前定制安装可以直接切换，也不代表可长期自动续期；上游对无浏览器方式的线上稳定性仍有明确保留。M0 验收时尚未改动现有 BOSS 安装、认证配置或会话，也未切换通道做线上尝试。随后独立 HTTP 首测返回 code 37；用户确认官方页面正常并授权一次对照后，使用内存中的当前会话资料成功取得原岗位“招聘中”，请求时没有浏览器连接。前置资料读取仍借助浏览器，认证冷启动与长期续期未验证；具体证据、因果边界和参数复用限制见 [岗位状态接口验证](岗位状态接口验证.md)。

正式主数据源选择仍待解决：需验证不经过人工准备的冷启动、既有会话复用、进程与主机重启恢复，以及认证到期后的处理。如果平台要求人工验证且没有可用的自动续期或服务认证机制，该来源就不满足严格无人操作目标，应改为补充来源并另选符合运行条件的主来源，不能将“失败后通知用户登录”称为无人值守验收通过。本轮仍不实现 M1、调度或浏览器管理。
