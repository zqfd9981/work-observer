# 完整产品使用与部署

2026-11-19。目标是单用户可部署研究产品，入口共用Python业务服务。实际能力与逐项证据见[完整验收台账](完整产品验收清单.md)，接口字段见[API合同](API合同.md)及运行页面 `/api/docs`、`/api/openapi.json`。

## 运行已有资料

```powershell
uv sync --locked
uv run --locked work-observer db-init
uv run --locked work-observer status
uv run --locked work-observer serve
```

打开 `http://127.0.0.1:8765`。`db-init`是增量升级；有库时先用SQLite backup API备份含WAL的已提交记录，核对旧表旧列全部行值保持一致。服务不自动采集或解除来源暂停。当前正式资料仍为15岗位、7正文、8摘要；未知发布时间保持未知。

页面覆盖岗位/公司、补录、持久研究、知识与偏好、个人匹配、检索与评测、观察与更新。研究可规划、读取本地和历史证据、必要时公开搜索及安全读取已返回网址、计算字面样本统计、形成六类带引用判断与缺口。查询及任务有数量、时间和上下文预算。查看结果不会自动再次调用模型。

工作画像保存来源快照、分析/提示/模型与记忆版本；来源、方法或人工纠正改变后旧画像标过时，按需重新分析。业务背景、任务、交付物、责任、能力、工具分别展示；领域可多标签，模型建议不覆盖人工纠正。个人匹配使用明确填写的结构化条件，不从自由文本猜个人履历。未知信息与已知不符分别列出。

研究自动保存过程到独立检查点库，报告仍可显式导出JSON/Markdown。继续中断研究沿用原范围、原文版本与累计预算，重启不自动消费额度。人工知识必须引用可核验JD；候选需采纳后才召回。修订、撤回、忘记与受影响报告有明确状态；忘记会清理关联派生上下文，独立导出副本及旧备份需使用者另行管理。

## 可分发演示

```powershell
uv run --locked work-observer demo-init --directory data/demo
uv run --locked work-observer serve --db data/demo/app.db --reports-dir data/demo/reports
```

只创建全新目录，4个原创合成岗位、5份快照；同一岗位有两个可比较的正文版本。全部标明`synthetic`，没有招聘请求，不能当成真实市场样本。重复初始化不覆盖旧演示资料；需要新的演示时指定另一个新目录。

没有模型时选择“仅整理证据”，会明确显示未执行模型分析。演示中的状态机、去重、版本比较、匹配和固定检索评测仍可离线操作。配置模型后产生的调用是实际调用，不把预录结果冒充当前执行。

## 命令行完整业务入口

`product <业务> [操作]` 的操作是可选位置参数，默认`list`。结构化输入用`--file`指定用户自己准备的JSON，页面/API从不接受任意本机文件路径。

```powershell
uv run --locked work-observer product profiles get --id <岗位ID>
uv run --locked work-observer product profiles analyze --id <岗位ID>
uv run --locked work-observer product profiles analyze --id <岗位ID> --offline
uv run --locked work-observer product match conditions
uv run --locked work-observer product match save --file 我的条件.json
uv run --locked work-observer product match run
uv run --locked work-observer product retrieval run --term Python --term RAG
uv run --locked work-observer product statistics run --term Python
uv run --locked work-observer product strategies list
uv run --locked work-observer product strategies create --file 别名候选.json
uv run --locked work-observer product strategies evaluate --id <候选ID>
uv run --locked work-observer product strategies activate --id <已通过候选ID>
uv run --locked work-observer product strategies monitor
uv run --locked work-observer product strategies rollback --text "明确回退原因"
uv run --locked work-observer product inbox unread
uv run --locked work-observer product inbox followup --text "需要继续核实的问题"
uv run --locked work-observer product watchsets list
uv run --locked work-observer product tasks list
uv run --locked work-observer product schedules list
```

个人条件JSON：`{"cities":["上海"],"salary_min":20000,"salary_unit":"month","employment_types":[],"desired_tasks":["上线"]}`。薪资按披露区间相交比较，不保证实际薪资；希望任务只检索当前有证据的画像，未命中保持待核实。

别名候选JSON：`{"name":"智能体同义词候选","aliases":{"Agent":["智能体"],"RAG":["检索增强"]}}`。固定评测合同由程序保存，候选不能改评分门槛。模拟夹具实际比较基线与候选，不代表真实市场召回改善。拒绝、回退的版本不能直接重新启用；需新候选及新验证。护栏失败会回退并保留事件，旧结果能识别受影响策略。

## 资料与记忆的CLI补充

CLI资料补充同样先核对：`import-csv <CSV文件>`只预览，确认后加`--commit`逐行保存；`import-image <图片文件>`只本机归档，显式加`--allow-model`才发送一次视觉请求，仍不写岗位。可用`--draft-file <新JSON文件>`保存待编辑草稿，对照原图核对后将`ocr_reviewed`改为`true`再用`import-jd --file ...`保存。演示图片使用`--data-kind synthetic`。个人记忆可用`memory-change <ID> forget --reports-dir <报告目录>`执行与页面相同的遗忘闭包。格式与真实组件验证见[资料导入](资料导入与OCR验收.md)。

## 观察任务与本地处理程序

观察规则保存版本和搜索范围；任务保留排队、进行、部分完成、失败、暂停拦截和中断进度。采集调用有上限，旧观察不因失败推断关闭。每日观察时段默认关闭，按北京时间配置，重复处理同一时段只创建同一任务。页面只入队，执行器必须显式启动：

```powershell
uv run --locked work-observer worker --once
uv run --locked work-observer worker
```

第二条持续检查已显式启用的本地时段，`Ctrl+C`停止。没有建立Windows系统计划任务。BOSS当前暂停，处理程序也会在创建来源连接前拦截；不能以启用时段绕过暂停。当前机器不要为展示去恢复来源或登录。真实长期无人采集仍未验收，离线回放仅验证机制。

## 备份与恢复

先停止页面与处理程序。备份包括业务库、目标库作用域的检查点、原始资料、公开网页与报告，不包括`.env`、模型密钥或招聘认证配置。备份包含私有来源原文，不能当作公开演示包。

```powershell
uv run --locked work-observer backup data/backups/我的完整备份
uv run --locked work-observer restore data/backups/我的完整备份 data/restored
uv run --locked work-observer status --db data/restored/app.db
uv run --locked work-observer serve --db data/restored/app.db --reports-dir data/restored/reports
```

恢复前逐文件校验SHA、数据库结构及外键，原文路径重新指向恢复目录。只恢复到全新目录，不覆盖原库；恢复的中断研究不会自动继续。备份使用完整性校验，没有加密或数字签名，需按私有文件管理权限和保留周期。密钥应由独立安全配置恢复，不能放进公开仓库。

## 部署访问模式

默认只有本机访问。准备远程单用户部署时，另行设置`WO_PUBLIC_ORIGIN`为固定HTTPS站点根地址、`WO_ACCESS_TOKEN`为密码管理器生成的至少32字符ASCII口令；两项同时配置。口令不放URL、不打印到日志。页面用口令换取12小时HttpOnly/SameSite会话；API可用Bearer。浏览器写操作还校验同源和CSRF令牌，Host必须匹配配置，失败登录有限额。不是多用户权限系统。

在目标主机用HTTPS反向代理转发到`127.0.0.1:8765`并保留Host，后端不直接向公网开放。服务器需要可用磁盘、稳定运行环境、独立密钥配置与正确卷权限。访问密钥轮换后重启会使旧会话失效。不要将真实JD、来源归档或备份放入公开静态目录。

仓库提供`Dockerfile`和`compose.yaml`作为部署配置。构建上下文排除`.env`、本地认证、数据库、原文、报告与Git目录；容器以普通用户运行、去除额外权限、端口默认只映射宿主机本地。第一次先在部署环境执行`db-init`，再启动服务；Linux数据卷须允许UID10001读写。容器内无宿主机招聘MCP安装或认证，不能据镜像启动就声称自动采集可用。

本机已验证源代码运行及独立wheel安装、迁移和演示。当前环境没有Docker命令，镜像构建、Linux卷权限和目标公网TLS/反向代理尚未实测；这些是部署到具体服务器前必须完成的环境验收，不写成已上线。未选择服务器、域名或产生部署费用，也未公开任何真实资料。
