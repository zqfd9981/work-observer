# 0.16 版本化标准检查与阶段验收

2026-11-19，单用户本地Alpha，持续目标保持active。本轮把0.15中已定位的否定误拦修复覆盖到新建标准研究，保留旧研究恢复时的检查口径；不新增真实模型调用，不据机制测试宣称语义质量提升。

## 新研究与旧轮恢复

新建标准研究默认识别“不能提升为必备”“不能将这些能力归为必备”“不拆出必备部分”等局部否定，不将其误当作正向必备信号。真正的必备条件与优先条件混写时仍被要求拆分。直接研究、CLI、HTTP与项目新轮共用同一入口，调用者不能传入隐藏检查参数来选择旧规则。

每个新轮在权威输入和结果中保存`qualification_validation`的版本及实现摘要，恢复前核对输入、检查点与执行实现一致；调用前及收到回复后也检查口径。若发生变化，保留已消耗调用后停止，不能通过重启重置预算或悄悄更换检查。

缺少独立检查字段的历史标准轮按旧兼容口径恢复，不回填新字段。可重建的v5方法摘要仍为`39a1ac28…dff24`，原输入和已保存历史消息保持；已有方法摘要不匹配时停止，不把未知旧实现重新标为当前方法。旧来源分项及反馈试验也继续受已有实现摘要约束，不能跨实现静默续接。

新标准执行方法登记`research-method-v6-versioned-qualification-validation`，摘要包含检查实现；原系统提示、要求性质政策及工具定义未变，不启用已撤回的v8实验提示。显式反馈登记v10、共享引擎来源分项登记v12，以区分实现。新标准的执行合同确实更新，不再声称所有新轮仍使用v5摘要。

已完成的研究、离线证据包及正文不足结果仍只能查看，不能借恢复覆写；本轮检查发现一处错误提示次序回归，已修正为先返回“本轮已结束”，失败测试收据保留。

## 项目、缓存与报告

等待中的旧项目可明确选择“更新材料或纠正口径后重查”。资料指纹原已包含方法摘要，因此只有检查口径变化也会被识别，无需伪造新正文。新轮仍计入原项目预算，原轮实际调用和整轮预留不变；已有依赖在新轮接受后才接续。

例如旧轮预留5次、实际用3次，新轮再预留5次、实际用3次，项目实际调用为6、预留为10，不能把两轮未用额度再开放。恢复旧轮则保持原max_calls和已用调用，继续同一检查点；不会另开整轮预算。

画像缓存继续按研究方法摘要判断有效性，旧缓存不会伪装成新版分析，也不覆盖历史。页面及新报告说明本轮使用的局部否定口径、恢复保持该口径，以及词面检查不等于语义支持；机器摘要保留在结构化记录中，不新增用户必须配置的版本开关。

## 实际机制验收

除合成回归外，使用真实已安装的0.15 wheel生成旧v5检查点：3次合成工具调用后中断，原上限5次。再由已安装0.16恢复，沿旧检查完成到累计5次，原输入、历史消息前缀及v5方法摘要保持，未新增检查字段。当前HTTP新标准轮用相同否定说明在3次合成工具调用内提交，CLI离线入口也记录新检查口径；实际模型及招聘请求均为0。

另验本轮中途检查变化时按已用1次停止、恢复前拒绝不一致检查；用户不能从服务或HTTP伪造旧规则。项目普通新轮、旧项目明确重查、预算预留、已完成结果保护，以及备份恢复同时保留新旧口径均被覆盖。独立安装包仍检查原来源分项、直接复核、项目补查、队列、日常流程及检索试用兼容。

完整测试、独立安装、源码/分发/安装资源一致、实际配置密钥扫描及数据保存证据位于私有`data/phase16-release`与`data/phase16-package`。版本迁移验证使用的合成工作区单独保存在`data/phase16-legacy-check`，不会混入真实研究评测。

## 保留的真实证据与缺口

正式23表旧值、原文、配置和code37暂停保持，仍15岗/7正文/8摘要。0.15的21运行、8协议、24方法审核、3普通拒绝及35文件备份再次逐值核对，原候选8调用未完成的状态不改，旧报告与冻结语料保持。没有为新标准检查补写成功结果或扩大旧试验额度。
