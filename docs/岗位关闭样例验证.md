# 真实岗位关闭样例

验证日期：2026 年 11 月 17 日。仅进行只读查验，未修改岗位状态、认证配置或现有业务表。

在用户 BOSS 收藏列表中找到：维智「大模型应用架构师（Agent方向）」，上海，25–50K，1–3 年，学历不限。打开实际详情页，页面明确显示 **“职位已关闭”**，同时仍可阅读职位描述。这是网站页面明确确认的关闭样例，不是根据搜索缺席、灰色卡片或随机岗位 ID 推断。

同一连接器的只读收藏接口原始响应成功，原始字段中该岗位 `jobValidStatus=2`。这证明收藏接口存在尚未被当前详情 MCP 返回的岗位有效状态信号；本例已由页面确认，不能由一个样例推断所有枚举值的含义。

再次调用当前 `boss_detail`，传入收藏中真实的岗位和访问标识，返回 `ok=false`、`BROWSER_SESSION_NOT_FOUND`。原始错误明确是缺少匹配的近期搜索上下文；浏览器实际仍已登录且能读取页面。因此，这次 MCP 错误不是网站返回“职位已关闭”的证据，详情平台请求在上下文校验阶段即未发送。

收藏原始响应没有提供当前连接器详情请求所需的 `lid`，没有编造参数或切换浏览器。尚未获得该关闭岗位的底层详情 JSON，不能声称关闭岗位必然使详情接口返回 `ok=false`，也不能声称详情原始响应含有相同状态字段。

本地资料仅保存在 Git 忽略目录：

- `data/raw/closed-job-investigation/20261117T123854Z_6272abb8/`：收藏接口原始响应及候选项，含内部访问标识，不对外分发。
- `data/raw/closed-job-investigation/20261117T123947Z_26c8c4db/`：真实 MCP 请求、失败响应及不含访问标识的 `closed-job-summary.public.json` 摘要。

另尝试过连接器的浏览历史接口，它返回 code 17“缺少必要参数”，没有当作空历史或关闭证据。

后续岗位生命周期设计应优先复用来源的明确状态，并保留原始字段与页面对照依据。需要进一步验证字段枚举及长期访问路径；当前没有实现周期状态巡检或 M2 定时任务。

同日补充验证：未收藏的正常岗位也能通过带上下文的详情 JSON 取得“招聘中”等状态字段；仅传 Job ID 的 JSON 请求返回 code 17。已登录浏览器用无查询参数、仅含 Job ID 的详情页网址，可分别显示正常岗位“招聘中”和本页维智样例“职位已关闭”。具体证据与批量复查限制见 [岗位状态接口验证](岗位状态接口验证.md)。
