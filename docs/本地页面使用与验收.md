# 本地页面使用与验收

> 本文保留G5历史验收。2026-11-19已扩展为0.4.0，已有库需先`db-init`增量升级，最新入口、持久恢复、画像/记忆/评测、资料补充与部署见[完整使用说明](完整产品使用与部署.md)。下文“重启丢失/未做持久化/已有库无需升级”等仅指旧G5阶段。

2026 年 11 月 18 日，G5 本地可操作界面。页面复用上一阶段 R01–R09 的业务能力，保留全部 CLI 命令、现有数据结构和招聘源暂停状态。

## 启动

在项目根目录运行：

```powershell
uv sync --locked
uv run --locked work-observer serve
```

然后在浏览器打开 **http://127.0.0.1:8765**。终端保持运行，按 `Ctrl+C` 停止。已有业务库无需初始化或迁移；服务不会自动采集、恢复认证或解除暂停。端口被占用时可换用 `serve --port 8767`，随后访问对应端口。

如需操作独立资料库：

```powershell
uv run --locked work-observer serve --db data/自己的资料.db --reports-dir reports/自己的研究
```

该数据库需要先通过 `db-init --db ...` 初始化。默认仍使用本地 `.env`、`data/app.db`、`data/raw/m1` 与 `reports`。页面不提供密钥输入或认证恢复入口，密钥仅在服务端读取。

## 可以在页面完成什么

| 页面 | 操作 |
| --- | --- |
| 岗位资料 | 查看岗位总量和正文数量；按关键词、城市、公司、完整度筛选；展开更多筛选处理薪资、学历、经验及来源 |
| 岗位详情 | 查看完整 JD、公司、工作地点、历史招聘状态、发布时间缺口、资料取得与归档时间；查看观察历史、核对来源或关联人工补充 |
| 公司档案 | 按名称查找公司、查看介绍和关联岗位；区分已有来源编号与身份未核实，不按同名强行合并 |
| 补充岗位 | 粘贴文本，或读取 UTF-8 文本／JSON 文件到表单，核对后保存；记录人工来源，支持稳定资料编号与原岗位关联 |
| 研究工作台 | 研究当前筛选范围，或勾选 2–5 个岗位后比较；可选择仅整理证据；显示真实等待状态与明确的失败反馈 |
| 原文依据 | 点击结论后的 E1/E2 等引用展开原文，继续查看来源文件完整性和内容版本；不重新访问招聘网站 |
| 已存研究 | 主动保存一次研究，之后再次查看；下载 JSON 或 Markdown，保留问题、口径、版本、原文及分析 |

筛选仍使用上一阶段的 SQL 语义：学历、经验按原文字面匹配；薪资以元为单位，同一计薪周期的区间相交；未知条件保留并单列，不默认当作符合。顶部总量表示整个资料库，列表上方数量表示当前筛选范围。手机上宽表格可单独横向滚动，不影响页面其他部分。

人工资料不会悄悄改写平台原文。相同人工资料编号、相同正文不会增加重复岗位或版本；有内容变化则保存版本。JSON 支持表单中的字段，以及 CLI 已有的 `source_published_raw`；不支持的字段或非文本值会在读取时提示，不静默混入上一份表单。未知字段留空，不用导入时间替代网站发布时间。文件与请求体上限约 500 KB。

## 研究与保存的边界

服务同时只执行一次研究，默认最多 10 次模型调用、180 秒、20 个候选；其他查看操作在等待期间仍可用。公开搜索、招聘采集均没有暴露为页面操作。勾选“仅整理证据”时明确显示原文证据包，不声称模型已分析。

只有点击“保存这次研究”才生成结果文件；同一次运行重复保存返回同一个结果，不复制多份。结果仍是上一阶段的 JSON／Markdown 格式，CLI 与页面互相可读，旧结果也能直接打开。

最近 20 次运行暂存在当前服务进程内；浏览器刷新可以恢复当前运行的轮询，但服务重启或进程退出会中断未结束的研究，未保存结果也不会持久保留。已保存研究不受影响。这不是通用任务队列或检查点系统。

页面与 HTTP 服务只绑定 `127.0.0.1`。不提供公网部署或多用户登录；校验本地主机、同源请求与写操作令牌，不开放跨域访问。原文、公司名、模型文字均按普通文本显示，不作为 HTML 执行；服务不把 Cookie、模型密钥和内部岗位访问参数交给页面，不返回原始文件的本机路径。

## 验收记录

- **真实页面读取：** 正式库仍为 15 个岗位、7 份完整正文、8 份摘要。正文筛选得到 7 个，岗位详情、公司关联和时间缺口均可查看。
- **真实模型：** 页面勾选两份已有 JD，经过 `query_jobs → read_job → read_job → finish_research → finish_research` 完成比较：完成提交在预算内修正一次，合计 5 次模型调用、12 条带引用判断。引用可展开并核对来源文件，结果已从“已存研究”再次打开；不是模拟或回放模型结果。
- **真实补录交互：** 在 `data/web-verification/ui-acceptance.db` 独立副本中粘贴一份真实 JD 人工复录，再从 JSON 重复导入，合计只增加 1 个人工岗位、1 份内容版本，保留 2 次导入观察；平台原文保持不变。
- **界面：** 已检查 1440 像素桌面及 390 像素手机宽度；引用弹窗、补录表单和重复导入反馈已实际点击验证。
- **自动化：** 最终 107 项测试通过（原有 95 项加 12 项 HTTP 集成检查），覆盖查询、补录、来源、研究、显式保存、下载、异常输入、同源边界和单次研究限制。Ruff、格式、JavaScript 语法及 49 个依赖一致性检查通过。现有 Starlette 测试客户端对 httpx 显示一项弃用提示，不影响本次检查或实际浏览器运行，未为此引入新依赖。
- **保留数据：** 无迁移、无删除、无招聘平台请求。对照备份核对正式库八张业务表的全部行值，原库保持不变；原有 code 37 风险暂停继续保留。

真实页面研究保存为 `reports/0e66ec50f7294b5faf33eef37e877255.json` 与 `.md`。本阶段隔离验收库、备份、截图和安全摘要位于 `data/web-verification/`；均由 Git 忽略，不将真实资料加入公开仓库。测试模拟模型仅用于机制检查，与上述真实模型调用明确区分。

底层 HTTP 入口位于 `src/work_observer/api/web.py`，页面资源位于同目录 `assets/`。仅将当前需要的读取、导入、研究与结果操作暴露为 `/api/*`，不提供任意 SQL、任意文件读取、采集、清锁、认证管理或系统任务入口。Starlette 与 Uvicorn 复用原锁文件中已经存在的版本，改为显式声明直接依赖；没有引入 Node 构建链或前端框架。
