# 观察补查项目遗忘开发记录

2026-11-20，按C01–C08和分析成果要求核对主流程，发现观察报告创建后续研究时，遗漏了已存在的遗忘传播关系。

## 已复现的问题

报告采用一条私人偏好，用户从报告保存补查问题并建立新项目，尚未执行模型。忘记原偏好后，报告与通知会清除，但新项目仍处于活动状态，私人目标和问题仍在。普通补查、共同正文子集和两侧面板补查三条实际入口均复现。

还复现了旧页面缓存入口：在遗忘前已准备好补查问题、尚未创建项目，遗忘完成后再提交创建，原来仍能将私人文本写入新项目。

## 当前行为

- 遗忘流程根据保存的报告来源键，收集这些报告派生的项目及执行。尚无执行记录的项目也纳入，不依赖模型是否召回过该记忆。
- 传播按现有来源依赖继续处理：项目研究形成的知识或后续观察报告，及其再次派生的研究项目，一并进入已有遗忘闭包。
- 沿用现有“先记录依赖ID、再擦除”的恢复记录。即使项目已清空来源键后中断，重新打开仍能清除该项目的私人记忆与后续内容；不新建状态或审批流程。
- 创建报告补查项目时，在原创建事务内确认对应报告尚未失效。遗忘后的缓存请求不再创建项目，页面给出中文说明。
- 所有查找限定当前研究库范围，未关联项目保持可用。原始岗位资料和归档引用不因派生目标遗忘而删除。

## 验证与边界

新增隔离用例覆盖三种入口的未执行项目、未召回记忆但通过报告继承的来源、多级报告/项目传播、来源键清除后的中断恢复，以及三种入口的缓存创建拒绝。验证清除了目标项目私人文本、保留了未关联项目及相同岗位原文，未产生模型调用。

相关项目遗忘、工作流、地图知识、观察关联、归档观察和记忆/隐私路径按影响范围回归。仅在临时合成资料上执行遗忘，没有对真实工作资料、旧研究或运行工作台执行遗忘，没有新增真实模型调用。
