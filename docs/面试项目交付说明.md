# Work Observer 面试项目交付说明

Work Observer 现在按个人面试项目收束交付。核心主线是：从已有 JD 和工作资料提出问题，带着原文研究，运行小实验检验理解，保留认识修正，再用于面试作答。后续只处理影响实际使用和面试演示的具体问题，停止自动扩展功能。

## 直接使用

当前本机演示入口：<http://127.0.0.1:19073/>。进入后点击“开始导览”，按页面下方的“下一步”演示完整闭环。

下次启动，在项目目录执行：

```powershell
.\start-interview-demo.ps1
```

演示使用临时合成资料和明确标注的预置模型回复，不读取正式资料或服务密钥，不连接招聘平台或外部模型。本地实验会实际计算。关闭服务后临时数据不保留，每次启动重新生成示例。它用于稳定展示工程流程，不能用来声称任意问题的真实模型回答质量已经验证。

源码首次准备需要 Python 3.13 和 `uv sync --locked`。普通工作台仍使用原有 `serve` 入口与明确配置的资料、模型服务；面试演示与真实资料工作台分别使用各自的数据和运行方式。

## 六分钟演示顺序

| 时间 | 页面导览 | 要讲清楚的价值 |
| --- | --- | --- |
| 0:00–0:45 | ① 从问题与资料开始 | 用户可以先带一个问题和一份资料开始，不必先补齐履历。 |
| 0:45–1:45 | ② 看懂实际工作 | 同样叫 Agent，任务与交付物仍不同；打开依据，区分原文、解释与要求性质。 |
| 1:45–3:00 | ③ Agent运行反例实验 | 展开实际输入和输出，点击“把这组输入放进实验台复跑”，再点“只运行，先看结果”。解释为何换请求编号会暴露反例。 |
| 3:00–4:00 | ④ 检查自己的理解 | 看用户原回答、反馈及未知；能复述不等于能解释条件，也不等于做过生产项目。 |
| 4:00–5:00 | ⑤ 连起分散认识、⑥ 认识修正后回看研究 | 旧认识、反例和修正分别保留，较新记录不会自动覆盖历史或变成真理。 |
| 5:00–6:00 | ⑦ 从练习整理面试材料、⑧ 迁移到新岗位 | 从实际练习回查证据，再说明哪些方法可迁移、哪些责任和能力还需验证。 |

讲完这条主线即可。检索评估集、单条样例诊断及面试、上下文合并等功能作为追问时的补充，不必把所有工具和页面逐个展示。

## 项目介绍

> 我开发了 Work Observer，一个基于已有招聘 JD 和工作资料的研究与面试准备工具。它把自然语言问题、原文引用、本地验证实验、认识修正和模拟作答连起来，让使用者不仅得到一段回答，还能回查依据、说明自己的观察和仍未验证的条件。
>
> 技术上使用 Python、Starlette、SQLite 和 LangGraph。模型通过受范围和预算约束的工具调查；资料、用户自述和研究判断分别保留。本地检索评估、反例实验和回答对照用实际记录支撑讨论，不把预置演示或局部指标当成真实业务效果。

## 技术追问重点

- **为什么需要 Agent**：问题不同，需要选择资料、读取原文、换表达补查和回查旧研究；范围、工具执行和预算由程序约束，模型不直接改原始事实。
- **怎样保证可追溯**：引用保留来源和位置，实验保存完整输入与实际输出；后续讨论和作答携带当时的材料与理解，修改不会自动重写旧回答。
- **怎样评估**：小样本检索评估逐条保留原问题、标签理由、漏回和额外返回。改变标签或问题会明确记录，不能把目标变了说成检索改善。
- **怎样体现产品闭环**：一条失败样例可以进入诊断、改条件重跑、针对性面试、回答反馈和两次作答对照；认识可以显式修正或搁置。

## 能力边界

可以展示已实现的完整用户流程、真实执行的本地计算、工程取舍与失败处理。已有 BOSS/MCP 归档 JD 是实际功能验证的资料来源之一；公开面试演示使用合成资料，不分发私人数据库、履历或密钥。

不能宣称预置演示是实时模型研究，不能把词面检索指标当答案准确率，不能把内存模拟当并发或生产系统验证，也不填写没有测量过的准确率、市场覆盖率、节省成本或业务收益。真实模型的稳定质量需要另行验证。
