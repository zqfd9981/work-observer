# 0.6 日常研究与受限试用阶段验收

2026-11-19，单用户本地 Alpha。目标继续覆盖持久研究、知识演进、真实质量改进和日常使用；本轮没有把工程机制完成当作完整愿景完成。

## 本轮实际修复

0.5 的真实历史研究副本复现了“上游人工纠正修订后，下游已采纳知识仍能被召回”。0.6 审核派生记录的来源运行、接续链、记忆版本及知识关系，修订、撤回、冲突、过期、源版本变化或明确人工拒绝会阻止继续默认复用。只读审计最多96节点/12层；缺失、循环或超额均保留待核对。旧运行、原文及人审历史保留，不用删除来掩盖失效。复现和修复证据在本机私有 `data/phase06-memory-repro`。

直接研究与画像原先能生成没有权威运行记录的来源编号；现在所有调用入口都会保存运行及材料指纹。作用域和检查点绑定业务库，关闭连接后仍可只读追溯。不能把随意填写的编号当作知识依据。

等待资料的步骤可在正文、历史或有效研究口径变化后显式建立补查。旧步骤回链新轮、保留用量和结果；重复导入同一正文不算新材料；重复提交不会创建多轮。离线原文整理可显式转成首轮模型分析。依赖的汇总须等替代轮次经人工核对后才继续，旧范围的步骤不能借补查扩大范围。

## 日常操作

1. 在岗位页导入或勾选已有资料，进入“日常研究流程”，保存明确目标、领域口径（可选）与累计预算。
2. 先核对最坏预算估算。缺正文时保留待补；超过累计额度时要求缩小范围，保留历史和已用量。
3. 默认执行只整理原文。明确勾选模型后，串行补做缺失或过时画像，复用仍有效画像，再进入调查、反例和审核后汇总。
4. 资料或人工核对未完成时释放执行；从关联项目核对原文或补查，再明确继续。形成的材料面板不冒充已核对的研究结论。
5. 同周期重复执行复用成果；后续周期比较原文、样本、方法和明确个人条件变化。没有可比时间序列，不输出市场趋势。

每批最多36次模型调用、900秒；整个流程最多72次、1800秒预留、12周期、20岗位。每份画像预留9次/235秒，项目预留24次/360秒。中断与失败不返还预留，需明确重试且继续占原累计预算。流程不采集招聘来源，不常驻运行。

网页、API 和 `work-observer workflow create/list/get/refine/run` 共用服务。CLI `run` 默认离线，`--allow-model` 才允许模型；JSON路径只由CLI本机使用，网页不接受任意文件路径。

## 检索旁路与有限试用

“检索与评测”中的“局部旁路与受限试用”只对冻结开发查询及明确岗位范围做比较。送审要求来源/题集/候选/基线/预留结果指纹相符、固定护栏达到门槛、独立人工标签声明和单独的明确人工授权。Agent辅助意见不能激活候选；人类身份与标签真实性仍依赖操作人负责声明，程序不伪造证明。

授权最多20次、24小时，只能使用已核对的开发查询组合和指定岗位。默认检索配置不变。到期、额度耗尽、来源变化、引用不实、遗漏基线覆盖、人工失败或待核对反馈均停止候选并回到基线；基线原始归档也缺失时返回“来源不可核对”、空证据及未知数量，不能报0命中。重复请求沿用同次结果和额度；停止后不能用旧缓存复活候选。

新冻结只保留8张来源语料表，并清除访问上下文和请求参数，不复制无关偏好、记忆和派生表。历史冻结包不被悄悄升级为独立人审。

## 日常流程专项验收

隔离服务链使用两份明确合成 JD 和一个按协议工作的模型替身，实际调用现有 `ProfileService`、持久项目、观察面板、差异和收件箱服务。两份画像之后，调查与反例停在待核对；测试代码执行核对动作后，关闭并重开检查点继续汇总，再核对汇总后周期才标完成。替身共执行20次工具轮转，没有额外真实模型或外网调用；这些核对动作是机制测试，不是独立人类语义评审。

专项还验证：默认保存不分析；默认离线仅提供材料面板，研究保持未完成；重复继续不复制面板或再付画像预算；修改一份正文后的明确离线新周期将原文变化和分析方法变化分别列示；完整新范围超过生命周期预算时零调用停止，明确缩小范围后保留原预算和历史。没有把部分画像完成或离线结果当作完整研究验收。

明确拒绝某画像的来源研究后，画像与同周期流程停止默认复用，先等待核对。显式重试计入额外预留，产生新的分析记录并保留旧结果；再次读取复用新的有效结果，不会因旧缓存冲突又返回被拒绝画像。这个回归也仅使用合成审核动作与模型替身，不声称新的分析已经独立通过语义评审。

故障恢复覆盖了画像中断后保留最坏预留、默认续接不重做中断画像、明确重试继续占累计额度，以及面板已落库但尚未关联流程时重试只得到同一面板。遗忘测试覆盖尚未关联聚合索引的项目来源键、流程擦除后的 ID 索引、通知清理故障后的重放；流程目标、面板和派生通知清除，原 JD 保留。研究项目提供12个物理轮次位置以容纳补查历史，但调用总额仍为24；离线关联项目明确转模型时，领取事务必须先在权威流程索引中补记24次/360秒预留，另一离线周期不能绕过流程总预算，伪造来源键也不能授权调用。

既有实际资料另做了零网络、零模型的隔离副本验收，证据在本机私有 `data/phase06-workflow/20261119-48c3fa10/acceptance.public.json`。从正式库只读 SQLite backup 复制，正式库旧列行值指纹保持一致：15个岗位、7份正文的全范围需要最多87次/2005秒，超过默认72次/1800秒，确实在调用前要求缩小；明确选取两份正文后，离线面板有效正文分母2、来源完整性失效0、Python字面出现2/2。虽然有两条原文整理结果行，仍显示完整当前画像0、画像待核对2，流程保持等待资料。这个结果只证明已有真实静态材料的流程、口径和数据保护，不证明语义研究质量或日常长期收益。

## 验收分级与未完成项

本轮优先采用隔离合成资料、协议替身和已有真实静态副本复现。它们证明预算、接续、依赖失效、范围及回退机制，不证明开放研究语义准确率或真实业务收益。正式资料未用于写入测试；招聘来源继续暂停。

0.5的真实研究12条判断仍待独立人工核对，真实检索开发/预留标签也不足。旧预留题已使用，不能再次声称全新盲验。本轮没有新增真实模型/公开搜索/招聘请求，也没有启用任何真实候选。因此“质量随真实反馈改善”和“长期日常可用”仍未验收完成。

后续实质工作：独立人工标签与足够新增盲验、据失败模式再改研究方法并做真实配对、持续实际使用及可比历史、目标部署环境运行。BOSS恢复不作为这些研发工作的前提，仍须另行明确授权。
