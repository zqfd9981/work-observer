# 演进比较来源时点开发记录

2026-11-20，检查领域观察报告到后续研究的实际路径，修复两个来源时点在复用时丢失的问题。

## 已复现的问题

同一岗位经历A→B→A→B时，面板仍指向最初A和首次B，但正文比较按快照ID查找最后一次出现。新测试实际失败于引用文档ID：输出引用了后来的观察文档和时间，而非面板冻结的来源。即使正文内容相同，这也会误导观察顺序和来源回查。

普通面板的补查问题原来没有附带两个来源截止；后续再出现C版时，研究可能读取当前C版或最近两版，偏离报告中的A/B对照。只有显式历史重建面板携带了截止条件。归档资料的普通复核还会把旧版本从项目范围中替换掉，失去两版比较所需的旧文。

## 本批行为

- 复用既有观察与入库时间，同时限定比较的较早和较晚侧。重复出现的相同快照不会把引用漂移到面板之后，较早侧也不会漂移到两面板之间的重复观察。直接查看岗位最近两版的原有行为保持。
- 所有带来源时点的报告在保存补查时附带两个明确截止，区分当时冻结观察和后来重建的历史来源，并要求分别读取对应历史原文。报告之后的材料另行说明，未读历史资料保持未知。
- 回到原研究补查时保留所选旧归档，并加入报告关联的同来源新版，供两版对照；不加入其他来源。沿用原累计预算、原回答及范围历史，保存问题不启动模型。
- 页面默认补查问题和完成条件同步改为报告两时点核对，说明归档两版会被保留，避免页面承诺与实际资料范围不一致。

30项相关Python检查通过，覆盖重复快照、当前/历史面板、归档两版、原研究关联、遗忘影响和原有最近两版比较。新增完整隔离路径在报告之后加入第三版，再从报告问题建立研究项目；工具替身通过范围确认、两次历史读取和回答共四次本地模拟调用完成，实际引用只含前两版，累计调用与历史面板保持正确。页面文本及转义检查、JavaScript语法和相关Python静态检查通过。
